# Seedance 2.0 官方能力与约束研究

## 研究口径

- 截止日期：2026-07-13。
- 确定事实只采用字节跳动 Seed、火山引擎、BytePlus、即梦/Dreamina 等官方或一手页面。
- 搜索结果中的第三方“Seedance”站点、教程和二手报道不作为事实依据。
- 置信度定义：`高` 表示官方页面明确陈述；`中` 表示官方页面或官方跳转能确认存在，但细节受登录态、地域或购买页限制；`未知` 表示截至研究日未在可公开访问的一手资料中确认。

## 结论摘要

Seedance 2.0 是统一的多模态音视频联合生成模型，核心价值不是单纯文生视频，而是把文字、图片、视频和音频同时作为生成、参考与编辑指令。官方明确其可一次输入最多 9 张图片、3 段视频、3 段音频以及自然语言，输出最长 15 秒的高质量多镜头音视频，并支持双声道和背景音乐、环境音、角色配音等多轨并行输出。

它对 AI 漫剧最有价值的能力包括：角色/场景/道具分离参考，分镜稿直接参考，镜头语言与动作节奏参考，提示词驱动的自动镜头规划，指定片段/角色/动作/剧情编辑，以及视频续拍。官方也明确承认多主体一致性、文字渲染、复杂编辑效果、细节稳定性和偶发音频失真仍需改进。因此 PRD 不能把“一次生成成片”作为成功假设，应设计镜头级生成、候选重试、人工选择、局部重做、后期字幕与音轨替换。

API 已由官方入口指向火山引擎方舟模型 `doubao-seedance-2-0`，BytePlus 官方定价页也明确显示国际版 Dreamina Seedance 2.0 API 已上线并提供 token package 购买入口。不过公开可访问页面没有给出可核验的单价、免费额度、并发、速率、任务队列、输入文件限制和 SLA，火山引擎模型详情页在未登录状态返回 401。因此所有成本和吞吐数字都应作为采购/技术接入前的供应商确认项，不可写死进 PRD 基线。

## 官方能力矩阵

|---|---|---:|---|
| 模型架构 | 统一的多模态音视频联合生成架构 | 高 | 将模型适配层抽象为多模态素材编排，而不是单一 prompt 输入 |
| 输入模态 | 文字、图片、音频、视频四种模态，可混合输入 | 高 | 素材库需要统一引用模型，支持角色图、场景图、道具图、动作视频、运镜视频、声音样本 |
| 同时输入上限 | 最多 9 张图片、3 段视频、3 段音频，再加自然语言指令 | 高 | 镜头任务需有素材预算和超限降级策略；不要让前端无限追加参考素材 |
| 参考能力 | 可参考构图、动作、镜头运动、视觉特效、声音等；可直接参考文字分镜稿 | 高 | 分镜编辑器应允许给素材标注“角色/场景/道具/动作/运镜/音色”等用途，并生成明确引用关系 |
| 文生/图生/参考生 | 官方展示 T2V、I2V、R2V，且强调混合模态参考生成 | 高 | PRD 需区分文生、首帧/图生、全能参考三类任务模板及其失败重试策略 |
| 输出时长 | 支持 15 秒高质量多镜头音视频输出 | 高 | 把单个生成任务限定为短镜头或短段落；长集必须由镜头编排和后期拼接完成 |
| 多镜头叙事 | 可输出 15 秒多镜头内容，并能按复杂故事、交互和动作描述执行 | 高 | 可让模型规划镜头，但平台仍需保存可编辑的镜头清单，不应只保存最终 MP4 |
| 视频编辑 | 支持针对指定片段、角色、动作和剧情做定向修改 | 高 | 设计“局部重做”入口和编辑指令历史；是否能保持未编辑区域像素级不变仍未知 |
| 视频续拍 | 支持基于提示词生成连续镜头、延长视频 | 高 | 支持从已选镜头创建续拍任务；跨多次续拍的质量衰减和最大总时长需实测 |
| 镜头控制 | 支持表演、光影、镜头运动控制；具备提示词驱动的镜头规划 | 高 | 分镜表单可暴露表演、景别、机位、运镜、光线、节奏等导演字段，并可回落为自然语言 |
| 动作与物理 | 官方强调复杂运动、多主体互动、物理规律还原和运动稳定性显著提升 | 高（能力主张） | 适用于动作戏，但仍需以可用率实测作验收，不能把官方 SOTA 主张转成产品 SLA |
| 主体/声音一致性 | 官方评测称对主体外观、声音、动作逻辑、风格和剧情一致性表现突出 | 高（官方内部评测） | 建立角色参考包与声音参考包；跨独立生成任务的一致性没有被官方明确保证，必须做项目级实测 |
| 已知一致性缺口 | 多主体一致性仍有优化空间 | 高 | 漫剧群像镜头应限制同屏主体数，或拆镜头、用剪辑完成；需要角色错位检测和人工复核 |
| 音频输出 | 双声道立体声；支持背景音乐、环境音效、角色配音多轨并行输出，并与画面节奏同步 | 高 | 生成任务应支持“要/不要配乐、环境音、对白”等意图；但官方未明确 API 是否返回可独立下载的分轨文件，后期混音仍需平台能力 |
| 方言/戏曲/歌唱 | 官方称相比上一代，对中文方言、传统戏曲和歌唱场景的指令响应准确性提升 | 高（相对能力主张） | 可列为拓展场景，不应作为 MVP 的强验收项，需按语言和声线单独测评 |
| 已知音频缺口 | 偶发音频失真仍未解决 | 高 | 必须提供静音重生、保留画面替换音轨、外部 TTS/配乐回退和音频质检 |
| 已知视觉缺口 | 细节稳定性、超写实感、动态活力仍需改进；文字渲染准确性和复杂编辑效果仍有不足 | 高 | 字幕、片名、招牌等文字不要依赖生成画面，统一后期叠加；需要候选生成和局部修复工作流 |

## 输入、输出与工程约束

### 已确认

1. **输入组合**：自然语言 + 最多 9 图 + 3 视频 + 3 音频可同时使用。
2. **输入用途**：可分别参考人物、场景、道具、构图、镜头运动、动作节奏、视觉效果和声音；官方示例明确用不同图片分别承载角色、场景和道具，并用分镜图控制景别、运镜、画面与文案。
3. **输出形态**：最长 15 秒的高质量、多镜头、同步音视频内容。
4. **声音形态**：双声道；可同时生成配乐、环境音、音效和角色配音。
5. **编辑形态**：提示词驱动的指定片段、角色、动作、剧情修改，以及续拍/延长。

### 未公开或未能从官方公开页面核验

以下内容不得由第三方教程补齐后当作官方事实：

- 输出分辨率、帧率、编码格式、码率、是否固定 1080p。
- 可选宽高比、横竖屏清单、透明通道、HDR、色彩空间。
- 输出时长是否只有 15 秒，是否支持更短固定档位或任意秒数。
- 3 段输入视频和 3 段输入音频各自或合计的时长、大小、分辨率、格式限制。
- 9 张图片的大小、像素、格式、透明图及动图限制。
- prompt 字数/token 上限、语言覆盖、固定随机种子、负向提示词、CFG/运动强度等参数。
- 编辑是否返回完整新视频，是否有遮罩、时间码、局部区域编辑或未编辑区域保持保证。
- 续拍一次可延长多少秒、最多续拍次数和累计时长。
- API 是否返回独立音轨文件。官方只说“多轨并行输出”，不能据此断言接口会提供可分离 stems。
- 视频水印、不可见标记、AI 内容标识和元数据策略。
- 生成延迟、P50/P95、超时、异步轮询协议、回调/webhook、任务保存期、下载 URL 有效期。

## 一致性评估及漫剧适配

### 官方确认的强项

- 复杂交互和复杂运动的可用率、运动稳定性、物理合理性提升。
- 对复杂故事、丰富角色互动和详细动作描述有更强指令遵循。
- 主体外观与声音保持、动作逻辑、风格和剧情连续性表现突出。
- 可通过参考图、视频和音频对角色、场景、动作、运镜及声音进行约束。

### 官方确认的缺口

- 多主体一致性仍有优化空间。
- 文字渲染准确性不足。
- 复杂编辑效果仍需优化。
- 细节稳定性、超写实感、动态活力仍需继续改进。

### PRD 建议

- 不承诺“整集人物绝对一致”。产品指标应改为镜头级可用率、候选命中率、角色身份错误率和人工修复成本。
- 使用“角色圣经 + 场景圣经 + 道具圣经 + 声音圣经”，每个镜头只挑选最相关素材，遵守 9/3/3 上限。
- 群像镜头默认拆分，优先用正反打、特写和剪辑维持叙事，而不是把所有角色塞进一个生成任务。
- 允许每镜头生成多个候选，并支持角色/动作/音频维度的失败原因标注。
- 所有字幕、气泡、片头片尾、品牌字样由平台后期合成，不放进模型画面生成验收。

## 音频能力及产品边界

官方明确 Seedance 2.0 是音视频联合生成，不是“先生成视频再自动配音”的简单串联。它能生成与动作和镜头节奏对齐的双声道音频，覆盖对白、音效、环境声和配乐，并对中文方言、戏曲和歌唱场景有相对上一代的改善。

但 PRD 必须保留独立音频链路：

- 官方承认偶发音频失真。
- 官方没有明确 API 会交付独立 stems，也没有给出采样率、位深、声道布局和音频编码。
- 未公开单段对白长度、多人对话稳定性、指定声线/声音克隆授权流程和音素级口型同步指标。
- 漫剧生产需要“保留视频、重新配音”“只换 BGM/音效”“静音导出”“外部 TTS 回退”和响度标准化。

## API、可用性、配额与价格

### 已确认

- Seed 官方模型页的“获取 API”中文入口指向火山引擎方舟控制台模型详情，URL 中的模型标识为 `doubao-seedance-2-0`。
- 英文入口指向 BytePlus 的 Seedance 2.0 活动/购买页面。
- BytePlus 官方定价页在 2026-07-13 明确展示：Dreamina Seedance 2.0 API 已上线，并提供 token package 购买入口。
- Seed 官方还提供即梦和 Dreamina 的在线体验入口。

### 登录态限制和未知项

- 火山引擎方舟模型详情页未登录时用户信息请求返回 401，不能公开核验模型参数、计费和配额。
- BytePlus 活动页公开壳页未渲染出可核验的套餐明细。
- 因此以下均为未知：单价及计费单位、是否对输入/输出分别计费、免费额度、预付 token 有效期、并发数、QPS、排队上限、日/月配额、失败任务扣费、退款规则、地域、数据驻留、企业 SLA、支持渠道。

### PRD 处理方式

- 成本模型使用可配置变量，不把任何第三方价格写入产品基线。
- 接入前必须由采购/技术负责人在已登录的火山引擎或 BytePlus 账号中保存官方报价、限额和协议快照。
- 模型适配层必须支持异步任务、超时、取消、幂等、重试、限流、成本记账和供应商切换。
- MVP 应保留人工使用即梦/Dreamina 的运营回退方案，避免 API 配额或审核变化使生产停摆。

## 内容政策、肖像与版权

### 官方明确项

Seedance 2.0 官方发布博客对展示素材作出专门说明：含人物参考的示例使用 AI 生成人物或已获适当授权的主体；如使用真实人物肖像作为视频生成主体参考，需要身份验证或事先取得合法授权。该要求应视为产品硬约束，而不是可选提示。

Seed 官网声明还明确，官网展示的文字、图片、视频、网页设计等内容由运营方或相关内容提供者享有版权/知识产权，未经书面许可不得复制、修改、传播、捆绑销售。它约束的是官网内容，不能推导为用户生成内容的商用授权。

### 截至研究日未找到 Seedance 2.0 专属公开条款确认的事项

- 用户生成视频的著作权归属和商业使用范围。
- 输入素材、提示词和输出是否用于训练或产品改进。
- 素材和任务的保存周期、删除机制、跨境传输和数据驻留。
- 公开人物、政治人物、未成年人、新闻事件、医疗/金融、色情、暴力、仇恨、自残等具体禁限规则。
- 第三方版权、商标、角色 IP、音乐和声音权利的审核、申诉和赔偿安排。
- 人脸/声音克隆的身份验证 API、授权凭证格式及企业批量创作流程。
- 输出水印、C2PA/内容凭证、不可见指纹及中国生成式 AI 内容标识如何落地。
- 审核失败错误码、申诉渠道和误杀处理 SLA。

### PRD 影响

- 上线前必须获取并法务审阅实际接入渠道的服务协议、AUP/内容政策、隐私和数据处理条款，不能以 Seed 模型宣传页代替。
- 建立素材权利台账：来源、权利类型、授权主体、地域、期限、用途、证明文件和撤回状态。
- 上传真实人像或声音时增加授权声明和证据留存；身份验证方式需等官方企业接入规则确认。
- 平台自身设置内容安全前置检查、人工复核、投诉下架和审计日志，不把全部合规责任外包给模型审核。
- 发布链路需独立实现 AI 内容标识和平台渠道所需水印/元数据，直至供应商提供可验证能力。

## PRD 必须列入的供应商确认清单

1. API 请求/响应 schema、模型版本策略、异步任务状态机和错误码。
2. 输出分辨率、帧率、宽高比、编码、时长档位和是否包含水印。
3. 图片/视频/音频输入的格式、大小、时长和总量限制。
4. 计费单位、输入参考是否计费、失败/拦截任务是否收费、token package 有效期。
5. 默认/最大并发、QPS、队列、日配额、扩容流程和 SLA。
6. 多轨音频是否以独立文件交付，还是只在最终双声道成片中混合。
7. 跨任务角色与声音一致性的官方建议和可复现参数。
8. 人像、声音授权和身份验证的企业/API 流程。
9. 内容审核类别、错误码、申诉、数据保留、训练使用、地域与跨境安排。
10. 商用权利、输出归属、第三方权利投诉和责任分配。

## 研究判断

Seedance 2.0 足以作为 AI 漫剧平台的核心镜头生成引擎候选，尤其适合“角色/场景/动作/运镜/声音多素材协同”的导演式工作流。但其官方边界决定了产品必须是镜头生产与后期编排平台，而不是一个整集一键生成按钮。MVP 的关键工程价值应放在素材权利与角色资产管理、9/3/3 参考编排、镜头级异步任务、候选与局部重做、外部字幕/配音回退、成本与审核审计，以及供应商可替换性上。
