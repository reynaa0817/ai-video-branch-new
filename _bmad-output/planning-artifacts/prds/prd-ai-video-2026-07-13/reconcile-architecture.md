# AI 漫剧平台 PRD 技术架构输入对账

## 1. 对账范围

- 输入：`技术架构一页纸.md`
- 对照主文档：`prd.md`
- 对照附录：`addendum.md`
- 本次只做审查与归档，不修改 PRD 或附录。

对账关注四类问题：输入遗漏、技术实现细节误入 PRD、产品能力缺口，以及 Must / Should 边界漂移。

## 2. 总体结论

架构输入的端到端主链路已被 PRD 大体吸收：idea 共创、概念样片、故事包、创作宪法与连续性账本、剧组资产、完整动态镜头、声音与剪辑、发布质检、可恢复编排、局部重做、管理员模型配置均有对应 FR 或 NFR。首版非目标与 Should 项的大方向也基本一致。

仍有四项值得在 PRD 定稿前处理的主要差距：

1. 五个关键确认闸门中的“粗剪成片确认”未形成明确产品要求。
2. 预算不足时“降低镜头复杂度但不截断故事、不降级成动态漫画”的受控方案被遗漏。
3. Should 级偏好记忆只保留了概念，未完整保留可见、可改、可删、可覆盖的用户控制权。
4. 权利台账、生成标识和生产审计被扩入 MVP Must；这可能有其他输入依据，但不能归因于本架构一页纸，需要保留独立决策来源。

此外，PRD 中出现了少量技术机制级措辞；架构输入中的“缓存”则没有被保留到附录。二者都是文档分层问题，不等同于产品能力缺失。

## 4. 主要差距

### 4.1 Must 控制点遗漏：粗剪确认闸门未被产品化

**输入证据：** 架构主线明确设置“闸门 4：粗剪成片”，且将五个高返工风险闸门作为效率前置控制。

**PRD 现状：** FR-18 定义自动组装粗剪、定位反馈与修改候选；FR-19 直接进入发布版本质检。没有明确要求创作者确认粗剪后才能进入最终质检或发布版本，也没有记录该确认。

**判定：** 这是产品能力和流程控制点的遗漏。它会把“五个少数确认”实际压缩为概念、故事/角色、分镜/样片和发布版本四类确认，改变原输入的人机协作节奏。

**建议归属：** PRD 的产品要求，而不是技术附录。后续修订时应说明粗剪确认的阻断范围、可修改对象、确认记录和确认后进入的阶段。

### 4.2 成本控制路径遗漏：预算不足只剩暂停或加预算

**输入证据：** 架构成本结果控制明确允许“预算不足时可降镜头复杂度，但不得截断故事或降级为动态漫画”。

**PRD 现状：** FR-11 在预算达到上限时暂停新增付费任务，继续生产的显式路径只有创作者提高预算；FR-14 只定义局部重做，FR-15 与 SM-C1 只定义不能降低成片形态。PRD 未向用户提供“保持完整动态与故事完整、降低镜头复杂度并重新估价”的受控备选方案。

**判定：** 这是产品能力缺口，不只是模型路由的技术细节。缺失后，成本控制在预算触顶时形成“加钱或停止”的二选一，弱化了架构输入中质量、效率、成本三维平衡的意图。

**建议归属：** PRD 描述用户可理解的降复杂度选项与不可突破的质量边界；具体如何改写镜头、选择模型或重新编排放入架构设计。

### 4.3 Should 能力缩减：偏好记忆缺少完整用户控制权

**输入证据：** 偏好记忆被定义为 Should，且明确要求跨项目软默认“可见、可改、可删、可覆盖”。

**PRD 现状：** 术语表保留“可解释的软默认”，MVP 后优先增强写有“创作者偏好档案、记忆中心和记忆使用提醒”，但没有明确承诺删除能力、单项目覆盖能力、关闭使用或修改来源内容。

**判定：** Must / Should 级别没有漂移，但 Should 的产品语义被削弱。记忆透明度不是仅靠提醒即可满足，尤其涉及跨项目数据使用与用户控制。

**建议归属：** 保留在 MVP 后增强，但补全为可见、可修改、可删除、可按项目覆盖或禁用，并与数据删除传播要求保持一致。

### 4.4 范围扩张：治理能力被提升为 MVP Must

**输入证据：** 架构一页纸的首版 Must 闭环未列出授权台账、生成内容标识和生产审计；其发布能力停留在可发布版本，多平台发布与反馈为 Should。

**PRD 现状：** FR-21 至 FR-23 以及 MVP 范围将项目授权台账、生成内容标识和生产审计记录全部纳入首版。

**判定：** 相对于本输入，这是明显的 Must 范围扩张。不过 `addendum.md` 表明这些要求来自权利与治理研究，因此不能仅据架构一页纸判定为错误。真正的问题是来源与决策链必须清晰：它们应被标注为由治理输入提升为 Must，而非架构输入原有 Must。

**建议归属：** 在后续 PRD 决策审计中确认内部试产阶段每一项治理能力的最小切片。若完整能力仅在对外运营前阻断，应区分“内部证据留存 Must”与“公开服务完整治理 Must”，避免内部 MVP 被不必要扩大。

## 5. 其他对账发现

### 5.1 定性目标遗漏：创作者归属感缺少验证方式

架构目标不仅要求故事完整、全片动态、设定一致，还要求用户有“创作者归属感”。PRD 通过自然语言反馈、设定锁定和创意匹配度间接表达了掌控感，但成功指标只测量作品与原始创意的匹配，没有直接验证用户是否认为作品是“我创作的”、AI 是否夺走作者感。这是容易被 FR 结构静默丢掉的定性输入，适合补充用户研究问题或反指标，而非强行制定未经验证的数字门槛。

### 5.2 概念样片“快速模式”没有可验证结果

PRD 保留了概念样片的受控预算和非正式属性，但 FR-3 没有定义相对于正式生产的快速交付目标或快速预览策略。SM-7 选择先采集前 20 部基线再定时长目标是合理的，因此当前更像开放验证项，而非必须立即补一个拍脑袋 SLA。应至少在基线采集时单列 idea 到概念样片的等待体验与放弃率。

### 5.3 管理员基础路由的边界略显模糊

架构把管理员节点配置中的“路由策略”列为 Must，同时把高级动态路由列为 Should。PRD 正确地将高级自动路由放到 MVP 后，并在 MVP 范围写入基础主备策略；但 FR-12 的可测试结果没有明确基础主备策略由谁配置、何时允许回退、回退前如何获得可见解释。FR-16 覆盖了恢复结果，附录 D 覆盖了机制，整体不是缺失，但验收边界可以更清楚。

## 6. 技术实现细节与文档分层

### 6.1 技术机制误入 PRD

以下措辞已从“产品结果”进入“实现手段”，且大部分在附录 C 已有适当归属：

- NFR-2 的“幂等语义”：产品结果应是重复请求不产生重复任务或重复扣费；幂等键等机制留在附录。
- NFR-6 的“不以长连接阻塞用户操作”：产品结果应是长任务不阻塞其他操作且状态持续可见；是否使用长连接属于架构选择。
- NFR-14 的“超时、重试、熔断”：产品结果应是供应商异常可恢复、有界、可暂停并可人工接管；具体熔断与重试机制已在附录 C 描述。
- FR-13 的“持久化状态”：其产品结果是页面、会话或节点中断后不丢失已完成成果。状态存储方式应由架构确定。

这些内容并未造成需求方向错误，但会不必要地约束架构，并与附录重复。PRD 后续润色时宜保留可测试结果、下沉机制措辞。

### 6.2 技术输入未进入附录：缓存

架构成本执行控制明确列出缓存。它没有进入 PRD是正确的，因为缓存是技术手段；但 `addendum.md` 的工作流机制建议同样未保留缓存，也没有说明缓存对象、命中失效与产物版本的关系。此项应在后续架构设计输入中留档，避免源输入静默丢失，同时不应直接补成产品 FR。

## 7. Must / Should / Could 边界核对

### 7.1 边界保持一致

- 偏好记忆仍在 MVP 后，保持 Should；问题仅是能力描述不完整。
- 用户自定义悬念比例与兑现节奏在 MVP 后，和 Should 一致。
- 高级模型路由与智能成本优化在 MVP 后，和 Should / Could 的分层一致。
- 完整资产影响分析与选择性迁移在 MVP 后，和 Should 一致。
- 多平台适配、直接发布与反馈在 MVP 后，和 Should 一致。
- 多人协作、资产市场、IP 衍生和 A/B 测试留在后续探索，和 Could 一致。
- 专业非线性剪辑器、通用工作流搭建器、默认全自动公开发布、动态漫画降级均保持首版非目标。

### 7.2 需要确认的边界漂移

- **治理能力上移：** FR-21 至 FR-23 相对架构输入从未列项扩为 MVP Must；需用治理研究与内部试产目标单独确认最小范围。
- **粗剪闸门下沉或丢失：** 架构 Must 主链路中的显式确认点在 PRD 中没有形成阻断要求。
- **成本降复杂度路径丢失：** 原输入的受控成本选项未进入 Must 或 Should，属于未分级而非主动降级。

## 8. 建议处置顺序

1. 在 PRD 定稿前确认粗剪确认是否仍为五个关键闸门之一；若是，补为明确可验收的产品要求。
2. 确认预算不足时是否允许“保完整动态、保故事完整、降镜头复杂度并重新估价”；若允许，补产品能力并把机制下沉架构。
3. 保持偏好记忆为 Should，但补全可见、可改、可删、可覆盖或禁用。
4. 为 FR-21 至 FR-23 补上独立的治理决策来源，并重新确认内部 MVP 的最小治理切片。
5. PRD 润色时移除幂等、长连接、熔断等实现机制措辞；在附录或架构设计中补记缓存。

## 9. 对账结论

本输入并未被整体漏吸收，核心生产闭环覆盖良好。当前最重要的不是增加更多技术描述，而是恢复两个直接影响用户决策与成本控制的产品能力——粗剪确认闸门、预算不足时的保质量降复杂度方案——并明确偏好记忆控制权与治理 Must 的来源边界。
