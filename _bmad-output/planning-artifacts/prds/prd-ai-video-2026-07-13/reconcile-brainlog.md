# 脑暴记忆与 AI 漫剧平台 PRD 输入对账

## 1. 对账范围与结论

- **输入名：** `brainstorm-ai-comic-platform-2026-07-13/.memlog.md`
- **对照产物：** `prd.md`、`addendum.md`
- **总体结论：** 用户明确确认的产品主线、共同创作体验、主动扩写及其红线、直觉反馈、概念样片、全片完整动态、先建剧组资产后批量生产、节点模型可配置、主备模型与质量档位、六项 MVP Must，以及质量/效率/成本三项核心因素，均已保留。用户对“静态叙事补位/轻动态混合成片”的否决也已正确覆盖早期教练建议。主要问题是一项明确数值决定遗漏，以及三组教练提出的具体机制被写成无标记的已确定要求。
- **对账性质：** 本报告只判断脑暴 canonical memlog 到 PRD/附录的保真度，不判断其他输入来源所引入需求的正确性，也不修改 PRD。

## 2. 主要差距

### 差距 1（高）：悬念比例的明确数值默认未被保留

- **用户明确决定：** “悬念比例允许用户设置；默认 10 集最多 3 集在高潮处直接切断”（memlog 第 58 行）。
- **PRD/附录现状：** FR-5 只写“首版使用固定默认的悬念节奏规则”，并把用户自定义比例放到 MVP 后（PRD 第 133–140 行）；附录也只写“固定默认叙事规则”（addendum 第 101–104 行）。
- **判断：** “10 集最多 3 集”这一可测试的明确默认值被抽象丢失。将“用户自定义比例”延期，与用户后来认可“六项 Must”的首版收敛大体一致；但即使首版固定默认，也应保留已确认的 `3/10` 数值，或明确记录该数值被后续决定覆盖。当前不存在覆盖记录。

### 差距 2（中）：教练建议的“五个确认闸门”被记为已解决硬要求

- **输入证据：** “少数关键确认闸门”和具体五个闸门均为教练 idea（memlog 第 22–23 行）；用户随后只是询问“呈现形式”，并确认“共同创作体验”，没有逐项确认五个闸门（第 24–26 行）。
- **PRD/附录现状：** PRD 将“少数关键确认闸门”写入产品愿景，并在 FR-3、FR-7、FR-19 等处形成强制门禁；附录 F 更将五类闸门写入“已解决的方案冲突”（addendum 第 101–106 行）。
- **判断：** “共同创作、降低新手决策负担、在高成本前确认方向”的目标有用户依据，但**具体五闸门组合**仍是教练方案。它不应在没有确认/假设标记的情况下被表述为已解决决定。

### 差距 3（中）：连续性方案名称与执行机制由教练 idea 升格为硬要求

- **用户明确边界：** AI 不得擅自修改用户设定，且必须保持角色前后一致；并确认“设定与基础资产一致性”属于首版六项 Must（memlog 第 30、79、81、84 行）。
- **教练补充方案：** “创作宪法”“连续性账本”、生成前注入约束、生成后连续性守卫检查，来自教练 idea（第 31 行）。
- **PRD/附录现状：** PRD 将这些方案作为正式术语和 FR-8/FR-10 的强制机制（PRD 第 69–80、164–189 行）；附录 C 继续规定连续性守卫的前后置行为（addendum 第 51–61 行）。
- **判断：** 用户确认的是一致性结果与红线，并未明确确认这套命名和实现形态。PRD 可以要求“锁定设定不可静默改变、跨阶段检查一致性”，但“创作宪法 + 连续性账本 + 守卫前后置检查”应标为待确认产品机制或下沉为架构建议，除非另有输入完成确认。

### 差距 4（中）：模型配置的若干教练细化项被写成 MVP 已确认边界

- **用户明确决定：** 每个工作流节点的模型和参数可在系统配置界面配置；每个节点同时支持主模型、备用模型和不同质量档位（memlog 第 70、73 行）。
- **教练补充方案：** 管理员/创作者权限分层、提供方/版本/凭证/配额/路由策略、配置版本化与产物快照、回退兼容性与质量底线，来自教练 insight/idea（第 71–72、74–75 行）。
- **PRD/附录现状：** FR-12 与附录 D 将上述大部分细化项列为无假设标记的 MVP 必须要求（PRD 第 204–212 行；addendum 第 63–70 行）。
- **判断：** 主备和质量档位保真；但“管理员专属、凭证与配额、版本快照、回退校验/暂停解释”等细化没有在该输入中获得用户明确确认。附录可以保留为架构输入，但不宜标成“已确认的 MVP 必须”，除非引用其他输入来源或补充确认。

## 4. 否决、修正与覆盖关系核对

1. **故事完整标准的修正已按最新决定处理。** PRD 没有停留在“每集必须解决冲突”的早期版本，而是允许单集高潮切断，并以完整短篇/故事弧的兑现判断完整性；只遗漏了 `3/10` 默认值。
2. **静态补位建议已被正确否决。** memlog 中教练曾建议预算不足时使用静态叙事补位（第 52 行），用户后续明确否决混合形态（第 64 行）。PRD、SM-C1 和附录 F 均以最新用户决定为准，没有残留冲突。
3. **高级路由、资产完整影响分析、偏好记忆被放到 MVP 后。** 这与用户认可“六项 Must 构成首版闭环”的收敛结果没有明显冲突。
4. **默认自动公开发布被排除。** 虽然该项最初是教练的 Won't 候选，用户对 MoSCoW 首版范围的总体认可使其作为首版非目标具有一定依据；PRD也没有将其说成用户逐项原话。

## 5. 非本输入可追溯项

PRD 中的 Web 形态、预算上限与精确提醒阈值、50–100 部内部样本门槛、授权台账、AI 标识、审计保留期、治理要求、具体成功率与 SLO 等，无法从本次脑暴 memlog 单独追溯。附录列出了 `MVP任务清单.md`、`技术架构一页纸.md`、研究材料等其他来源，因此本报告不将它们直接判定为错误；但在 PRD 的输入追踪中应保持其来源可辨，避免被误认为用户在本次脑暴中已确认。

## 6. 对账结论

本输入的主线和绝大多数用户决策已被可靠吸收，尤其是主动共创、设定一致、概念样片、完整动态、资产复用、节点模型配置和三维验收重点。需要优先修复的是 `3/10` 悬念默认值的遗漏；其余主要风险是把教练提出的闸门组合、连续性机制和模型配置细化写成已确认要求。建议后续 PRD 更新时，对这些项逐一执行“补充用户确认、标注假设、或降级到附录建议”三选一。
