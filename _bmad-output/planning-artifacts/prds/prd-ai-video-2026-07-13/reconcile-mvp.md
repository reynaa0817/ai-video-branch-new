# AI 漫剧平台 PRD 与 MVP 任务清单对账

## 1. 对账范围

- **原始输入：** `MVP任务清单.md`
- **目标文档：** `prd.md`
- **补充文档：** `addendum.md`
- **对账目标：** 检查原始输入是否在 PRD 或附录中得到保留，识别遗漏、语义漂移、Must/Should/Could/Won't 边界变化及验收缺口。
- **限制：** 本报告只记录差异，不修改 PRD 或附录。

## 2. 总体结论

六项原始 Must 的主干能力均能在 PRD 中找到对应要求，完整动态、故事闭环、设定一致、可恢复编排、并行生成、局部重做、基础模型配置等核心方向没有发生根本偏离；原始 Should、Could、Won't 的大部分边界也得到保留。

但当前 PRD 不能视为与原始 MVP 清单完全等价，主要有三类差异：

1. **Must 范围扩张：** PRD 将作品级预算控制，以及授权台账、生成内容标识和生产审计记录纳入 MVP 范围，突破了原清单“首版只交付已经确认的六项 Must”的边界。
2. **优先级上调：** 原清单 Could 中的“智能成本优化”被并入 PRD 的“MVP 后优先增强”，相当于从 Could 提升为 Should。
3. **验收语义弱化：** 粗剪确认闸门、阶段完成后才允许下游消费、概念样片认可内容继承、历史资产版本保留等要求没有形成同等强度的可测试结果。

因此，结论为：**核心产品闭环基本对齐，但存在 2 项范围边界变化、1 项明确优先级漂移及若干验收缺口；在锁定 MVP 承诺前应由产品负责人明确接受或纠正。**

## 4. 遗漏与语义漂移

### 4.1 高：粗剪关键确认闸门被弱化

- **原始语义：** M5.2 明确要求设置“粗剪成片”关键确认闸门，用户审阅后才能完成必要修正并进入发布版本确认。
- **当前表达：** FR-18 规定用户可以定位并反馈粗剪问题；FR-19 规定发布版本确认记录，但没有规定粗剪必须由用户明确放行，也没有阻止未确认粗剪进入下一阶段。
- **影响：** “关键确认闸门”从流程阻断条件变成一般反馈机会，可能导致系统在未获方向确认时继续产生后期成本，也削弱创作者归属感和控制权。
- **建议补验收：** 未记录粗剪确认时，不得创建候选发布版本；确认记录应包含确认人、时间、粗剪版本和未解决问题。

### 4.2 中：阶段完成门控缺少直接验收

- **原始语义：** M6.1 要求定义每个节点的输入、输出和完成状态，下游只能消费已完成的阶段产物。
- **当前表达：** FR-13 验收状态持久化和恢复，NFR-3 要求通过质量检查才进入下游，但没有覆盖所有节点的“完成状态 + 输入输出契约 + 下游消费限制”。
- **影响：** 架构和测试可能只实现恢复能力，却没有统一的阶段完成语义；半成品或过期产物可能被下游任务消费。
- **建议补验收：** 每个节点必须声明输入版本、输出版本和完成状态；非完成、已失效或未通过门控的产物不能成为下游任务的有效输入。

### 4.3 中：概念样片认可内容的继承链缺失

- **原始语义：** M1.2 要求方向确认后，正式脚本阶段能够继承样片中被认可的内容。
- **当前表达：** FR-3 允许保留、修改或丢弃样片方向，FR-6 生成故事包，但两者之间没有可测试的继承关系。
- **影响：** 用户认可的角色感觉、视觉方向或戏剧卖点可能在故事包阶段丢失，造成“样片确认了但正式生产又变了”的语义断裂。
- **建议补验收：** 样片确认时形成可追溯的认可项；故事包和后续视觉资产必须引用这些认可项，偏离时需提示并重新确认。

### 4.4 中：历史资产版本保留要求变弱

- **原始语义：** M3.2 验收明确要求旧资产版本和已有镜头引用关系不丢失。
- **当前表达：** FR-9 要求同一角色默认引用同一确认版本、引用关系可查询，并说明 MVP 保留基础版本与引用，但未直接要求旧版本不可覆盖或删除。
- **影响：** 仅实现“当前版本 + 当前引用”也可能被判为通过，无法保证历史镜头可复现、发布版本可追溯或局部重做稳定。
- **建议补验收：** 创建新资产版本不得覆盖被阶段产物或发布版本引用的旧版本；历史引用应可查询并可用于重现对应镜头输入。

### 4.5 低：持续阶段预览缺少完成定义

- **原始语义：** M6.1 要求提供可持续预览的阶段成果，使用户始终接近可发布版本。
- **当前表达：** MVP 范围列出“持续预览”，FR-15 要求已完成镜头持续预览，NFR-6 要求长任务展示进度，但没有定义哪些阶段必须形成可播放或可理解的预览。
- **影响：** “持续预览”可能退化为任务进度条，而不是用户可判断方向的阶段成果。
- **建议补验收：** 为概念、故事/分镜、镜头生产和粗剪阶段分别定义最小可预览产物及可反馈入口。

## 5. Must / Should / Could / Won't 边界对账

### 5.1 Must 范围新增

#### A. 作品级预算上限与成本控制被扩展为独立 Must

原始清单把成本控制作为最高验收维度，并在概念样片、资产复用、缓存、局部重做和管理员配置中体现，但六项 Must 并未明确要求用户设置作品预算上限、生成前展示完整成本区间、70%/90% 提醒及 100% 自动暂停。

PRD 通过 FR-1、FR-11、MVP 范围和 SM-10～SM-12 将其升级为完整的首版交付能力。这是合理的成本治理增强，但属于**原输入之外的 Must 扩张**。其中 70%/90% 阈值已标记为假设，其余预算上限与暂停机制则被直接承诺。

#### B. 权利、标识与审计被纳入 Must

原始六项 Must 仅要求阶段产物和模型配置快照可追溯，没有项目授权台账、AI 生成内容标识、授权撤回/过期阻断等交付项。PRD FR-21～FR-23 和 §6.1 将这些能力列为 MVP 范围，且 FR-21、FR-22 带有发布阻断验收。

这是最显著的边界扩张：原清单声明“首版只交付已经确认的六项 Must”，而 PRD 实际形成了第七组治理能力。若治理能力只是外部商业化前置条件，应与阶段 A 的“有处理路径”保持一致并明确哪些是内部 MVP 必做；若确为首版必做，则应回写产品决策记录，正式承认新增 Must。

## 7. 建议的产品决策清单

以下不是直接修改建议，而是 PRD 定稿前需要显式确认的边界决策：

1. **确认新增 Must：** 预算控制与权利/标识/审计是否正式成为六项 Must 之外的首版交付承诺；若不是，明确内部 MVP 与外部商业化准备的分界。
2. **恢复粗剪闸门语义：** 确认粗剪是否必须由用户明确放行；若是，应形成阻断型可测试结果。
3. **确认智能成本优化优先级：** 保持原 Could，还是正式提升为 Should。
4. **补齐四条验收链：** 阶段完成门控、样片认可内容继承、历史资产版本保留、阶段可预览产物。
5. **保持追溯口径一致：** 将“关键输入可追溯”与原清单“每个阶段产物可追溯到节点模型配置快照”的口径统一，避免测试范围缩小。

## 8. 对账结论

PRD 已成功吸收原始 MVP 清单的大部分产品意图，六项 Must 的核心闭环可以识别并用于后续设计与架构工作。当前主要风险不是核心功能遗漏，而是**范围扩大后仍沿用“六项 Must”表述，以及部分流程闸门从强制验收退化为一般能力描述**。在上述边界决策与验收缺口关闭前，建议将 PRD 保持为 `draft`。
