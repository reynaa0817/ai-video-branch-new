# AI 漫剧创作平台 PRD 来源提取

本文件忠实提取以下四份既有输入，不新增产品方向，也不修改 `prd.md`：

4. `.memlog.md`

## 适合进入 PRD 的事实与决定

### 产品定位、用户与价值

- 产品定位是面向缺乏影视制作经验、追求快速产出的非专业创作者的“AI 漫剧导演工作室”，不是单次视频生成工具。
- 用户以自然语言表达一个模糊 idea，AI 创作团队主动完成创意扩写、故事规划、剧组资产、分镜和镜头生产、配音配乐、剪辑字幕直至发布版本；目标成果是故事完整、全片动态、设定一致，并让用户保有创作者归属感的作品。
- 核心价值是“兑现创意”：缩短从脑内想象到首次可观看成果、再到可发布成片的距离，减少等待、决策过载、创作半途而废与全量返工造成的创作动量丢失。
- 产品优先保证作品完成，再逐层提高质量；完整短篇或阶段性故事弧必须形成可理解的叙事闭环。

### 共同创作体验与用户主权

- AI 面对一句模糊 idea 时默认大胆扩写人物、冲突、世界观、反转和剧集钩子，不要求新手先掌握影视语言。
- AI 不得擅自改变用户设定；用户的角色、关系、能力、外形、世界规则和关键意图需要形成不可轻易偏离的创意锚点，并在后续阶段保持一致。
- 用户可以用“喜欢/否决”或自然语言直觉反馈参与创作，系统把反馈转译为故事、镜头、表演或声音修改；用户不需要直接操作专业参数。
- 产品采用“少数关键确认闸门、大量默认自动执行”：只有改变作品方向或可能造成高额返工时才要求确认。来源中提出的五个闸门为创意简报、故事大纲与角色圣经、分镜与样片、粗剪成片、发布版本。
- 提交 idea 后优先交付高潮样片或概念预告，作为首次惊喜时刻并提前验证核心角色、视觉风格和戏剧卖点；样片为非正式内容，可继承、改写或丢弃。

### 首版范围与产品能力

- 用户已认可六项 Must 构成从 idea 到完整漫剧的首版最小闭环：
  1. 共同创作入口与概念样片。
  2. 故事、脚本与分镜。
  3. 设定与基础资产一致性。
  4. 以 Seedance 2.0 为主要视频生成模型的全动态镜头生产。
  5. 配音配乐、剪辑、字幕与成片。
  6. 可恢复编排与管理员模型配置。
- 首版应允许中断后从已完成阶段继续、失败后恢复、持续预览阶段成果、并行生成互不依赖的镜头，以及只重做受影响的局部内容。
- 正式批量镜头生成前先建立可复用剧组资产，覆盖角色多视图与表情、服装、场景、道具、声音、动作参考和风格规则，以支持跨镜头一致性与复用。
- 普通创作者默认不选择模型；系统管理员按工作流节点配置模型提供方、版本、参数模板、凭证、配额、主备模型和质量档位。备用模型不满足角色一致性或完整动态底线时，系统必须暂停并解释，不能静默降级。
- 首版最终交付用户确认的发布版本，但不默认自动公开发布。

### 质量、叙事与验收方向

- 可发布成片的所有镜头必须是完整动态视频，不以动态漫画、静态叙事或“关键镜头高动态、普通镜头轻动态”作为常规降级方案。
- 预算或时间不足时可以降低镜头复杂度或运镜，但不得截断故事，也不得突破完整动态和设定一致性的质量底线。
- 故事完整性按完整短篇或阶段性故事弧判断。单集可以在高潮处切断制造悬念，但不能持续用悬念代替冲突兑现；故事弧结局不得切断。
- 已确认的悬念方向是：比例允许用户设置；默认每 10 集最多 3 集在高潮处直接切断，连续悬念不超过 1 集，最多每 3 集兑现一次。该能力应属于首版还是首版后增强，四份来源存在冲突，见下文。
- 平台成败的三个最高维度是视频质量、生成效率和成本控制；首版功能必须至少明确贡献其中一项。
- 已给出的成功指标方向包括：故事完整度、全片动态达标率、用户设定与角色连续性、创意匹配度、首次惊喜时刻用时、idea 到发布版本周期、成片完成率、局部重做替代全量返工效果、单作品生成成本、预算偏差，以及资产复用/缓存/模型路由带来的节省。

### 首版后与明确边界

- Should：创作者偏好记忆与透明度、悬念节奏配置、模型策略组高级路由、资产变更影响分析、多平台发布与反馈回流。
- Could：多人协作、资产市场、IP 衍生、A/B 测试与智能成本优化。
- Won't：专业非线性剪辑器、通用工作流搭建器、默认全自动公开发布、以动态漫画替代完整动态成片。

## 更适合进入 addendum 的技术机制

以下内容可以在 PRD 中保留其用户可感知结果或约束，但具体“如何实现”更适合进入 `addendum.md` 或后续架构设计：

- **生成前注入、生成后守卫**：创作宪法与连续性账本如何在每个生成节点前注入约束，节点完成后如何检查角色状态、世界规则和锁定设定冲突，以及如何阻断不一致产物流入下游。
- **节点编排机制**：各节点的输入、输出、完成状态、阶段产物持久化、依赖关系、失败恢复、后台并行和局部重做的具体编排设计。
- **模型策略组与路由机制**：主模型、备用模型、快速预览模型、高质量模型之间如何按质量、预算、时限、可用性和内容能力进行动态路由、兼容性校验和自动回退。
- **配置追溯机制**：节点配置版本化、每项产物保存实际模型配置快照，以及这些快照如何用于复现、审计、成本统计和批量迁移。
- **资产数据与依赖机制**：资产版本、镜头对资产版本的引用关系、缓存键、旧版本锁定、变更影响分析和选择性重生成的具体实现。
- **低成本预览机制**：概念样片的快速模式和受控预算如何落地，正式阶段如何复用认可内容与缓存结果。
- **交互呈现细节**：作品旁自然反馈入口、最多一个上下文追问、可视化修改候选、修改前后对比、记忆中心和记忆使用内联提示等界面机制。
- **质量检查实现**：完整动态、角色一致性、故事信息完整性和模型兼容性的检测方法、阈值与失败定位方式。

## 冲突与漂移

| 主题 | 来源表现 | 需要 PRD 流程明确的点 |
|---|---|---|
| 悬念配置的首版归属 | `brainstorm-intent.md` 的 Must 写“支持悬念比例及兑现节奏”，Should 写“更完整的悬念节奏配置”；`MVP任务清单.md` 明确首版不实现用户可配比例，将其整体放入 Should | 明确首版究竟只保证故事兑现原则，还是同时交付可配置比例；当前不能同时按两种范围表述 |
| 资产版本与引用关系的归属 | `brainstorm-intent.md` 将“资产版本、镜头引用关系与变更影响分析”整体列为 Should；`MVP任务清单.md` 和架构一页纸把资产版本与镜头引用纳入 Must，仅将完整影响分析留在 Should | 确认是否接受后两份材料对 Must 的扩展 |
| 创意简报闸门的落点 | 产品意图、架构图和 memlog 都列出“创意简报”闸门；MVP 清单以概念样片的“保留、修改或丢弃”方向确认为主，没有单独命名或验收创意简报闸门 | 明确它是独立产物/闸门，还是概念样片方向确认的一部分 |
| 模型路由的 Must/Should 边界 | 管理员节点配置、主备模型和质量档位被确认为 Must；按质量、预算、时限、可用性和内容能力的高级动态路由被列为 Should；架构图将二者紧密组合 | PRD 需把“基础配置与质量底线”同“高级动态路由”分开，避免首版范围扩张 |
| 静态叙事降级 | memlog 中较早的教练建议允许预算不足时用静态叙事补位；用户随后明确否决混合动态形式，最终产品意图、MVP 与架构材料均要求全片完整动态 | 早期建议已被后续用户决定取代，不应进入 PRD 当前要求 |
| 偏好记忆 | 共同创作过程中用户明确提出长期记忆、记忆中心与使用提醒；最终 MoSCoW 将其放入 Should | 它是已确认的产品方向，但不是首版 Must，不应误写成首版交付承诺 |

## 仍缺失的信息

- **量化目标缺失**：视频质量、效率和成本只有指标方向，没有目标值、统计口径、基线、观察周期或最低通过阈值。
- **产品形态缺失**：尚未明确 Web、移动端、桌面端还是多端，以及普通创作者前台与管理员后台的首版载体。
- **用户与场景深度不足**：只有宽泛目标用户，没有具名端到端用户旅程、典型题材、作品时长/集数、创作频率、可接受等待时间和预算范围。
- **发布范围不清**：明确不默认自动公开发布，但“可发布版本”的导出格式、分辨率、宽高比、时长、字幕/音轨要求和首版交付渠道未定义。
- **商业化缺失**：brainstorm goal 提到商业化，但四份材料没有价格、套餐、配额、计费单位、成本上限或付费意愿结论。
- **模型与依赖风险未展开**：Seedance 2.0 被指定为主视频模型，但未给出可用接口、配额、能力边界、内容政策、地区限制、SLA 或替代条件。
- **质量验收可操作性不足**：故事完整、角色一致、创意匹配和全片动态尚无可执行的评审标准、自动/人工责任边界和用户否决后的通过规则。
- **内容安全与权利治理缺失**：未说明输入素材和生成内容的版权、肖像/声音授权、内容审核、未成年人、隐私、数据保留和模型训练使用规则。
- **项目与资产管理缺失**：未定义项目创建、保存、版本历史、删除、导入/导出，以及资产归属和跨项目复用权限。
- **非功能要求缺失**：除可恢复和可追溯方向外，未给出性能、并发、可靠性、可用性、安全、可观测性、备份恢复和运维指标。

## 忠实提取说明

- 本提取优先以 `.memlog.md` 中标记为用户决定/用户方向的内容，以及四份材料的最终 MoSCoW 归纳为事实依据。
- 教练提出但未被用户确认的点只在它已被最终材料吸收时列为当前方向；其具体实现机制归入 addendum，未把候选想法升级为新产品决定。
- 对相互冲突的材料只列出冲突，不替用户选择范围。
