# AI 漫剧平台 PRD 产品意图对账

## 1. 对账范围

- **原始输入：** `brainstorm-intent.md`
- **承接文档：** `prd.md`、`addendum.md`
- **检查目标：** 识别原始产品意图在 PRD 结构化过程中出现的遗漏、语义漂移，以及被 FR/NFR 结构弱化的体验、语气和产品边界。
- **限制：** 本报告只提出差距，不修改 PRD 或附录。

## 2. 总体结论

主产品闭环被较完整地保留：非专业创作者、idea 到成片、AI 主动扩写、创意锚点、全片动态、故事闭环、连续性、概念样片、局部重做、可恢复编排、预算控制、Seedance 主引擎与管理员节点配置均能在 PRD 中找到明确承接。

但仍有 **5 项值得在 PRD 定稿前处理的主要差距**。其中最明显的是悬念节奏的 MVP 边界发生改变；其余多为原始输入中的体验约束在 FR 化后变成概括性表述，导致后续 UX、验收或架构无法可靠恢复原意。

## 3. 主要差距

### 差距 1：悬念节奏的具体规则丢失，用户配置能力被降级

**类型：** 语义漂移 / 范围漂移（高）

**原始意图：**

- 默认每 10 集最多 3 集直接在高潮处切断；连续悬念不超过 1 集；最多每 3 集兑现一次；故事弧结局不得切断。
- 明确写有“悬念比例允许用户设置”。
- Must 范围写有“支持悬念比例及兑现节奏”，Should 仅把“更完整的悬念节奏配置”放到闭环稳定后增强。

**PRD / 附录现状：**

- FR-5 只写“首版使用固定默认的悬念节奏规则”，没有保留任何默认数值。
- FR-5 与 MVP 后增强均把“用户自定义悬念比例”整体移到 MVP 后。
- addendum.md 的“已解决的方案冲突”再次确认了这一降级，但没有说明它为何可以覆盖原始输入中“允许用户设置”和 Must 范围的表述。

**影响：**

- 测试无法判断“固定默认规则”究竟是什么，叙事约束不可验收。
- “基础比例设置”与“更完整配置”在原始输入中可能是两个层级，PRD 将二者合并为同一个后续能力，扩大了 MVP 削减范围。
- 这是明确的产品范围变化，不应仅作为 FR 重写后的默认结论存在。

**建议补回的意图：** 保留默认数值为可测试结果；明确区分 MVP 的基础悬念比例设置与 MVP 后的高级节奏配置。若确实决定 MVP 完全不允许用户设置，应将其标记为相对于原始输入的已确认范围变更及理由。

### 差距 2：创作者偏好记忆只保留了名词，完整控制权与透明度丢失

**类型：** 体验边界丢失（高）

**原始意图：** 创作者偏好档案是跨项目的“可解释软默认”，用户可以查看、修改、删除、继承、覆盖或关闭；每次使用时须提示来源与影响。作品连续性账本与跨项目偏好档案也被明确区分。

**PRD / 附录现状：**

- 术语表保留了“创作者偏好档案”“可解释的软默认”和首版后增强。
- MVP 后增强只写“创作者偏好档案、记忆中心和记忆使用提醒”。
- 没有承接查看、修改、删除、继承、覆盖、关闭等控制面，也没有要求说明偏好来源及对本次生成的具体影响；addendum.md 同样未保存这些细节。

**影响：** 后续做记忆能力时，团队可能只实现“读取历史偏好 + 提醒已使用”，却遗漏用户撤回、纠正、项目覆盖和关闭学习等核心产品边界。该差距同时涉及用户信任、隐私和创作主权。

**建议补回的意图：** 即使该能力仍属于 MVP 后，也应在附录或后续范围中完整保存控制权清单和透明度要求，避免在阶段迁移时不可逆丢失。

### 差距 3：五个关键闸门没有在 FR 中形成完整、可测试的状态约束

**类型：** 功能承接不完整 / 自动化边界变薄（高）

**原始意图：** 建议闸门为创意简报、故事大纲与角色圣经、分镜与样片、粗剪成片、发布版本；除此之外默认自动推进并允许用户按需介入。原则是只在改变方向或可能造成高额返工时确认。

**PRD / 附录现状：**

- FR-3 对概念样片设置了确认约束；FR-7 只明确故事与角色、分镜与样片两个闸门；FR-19 记录发布版本确认。
- FR-2 没有把创意简报定义成进入后续方向的明确闸门。
- FR-18 生成粗剪，但没有要求用户确认粗剪后才能进入发布版本处理。
- “非闸门步骤默认自动推进、用户可按需介入”只作为愿景语气存在，未形成状态机或验收要求。
- addendum.md 虽列出完整五类闸门，却与主 PRD 的 FR 可测试结果不一致。

**影响：** 架构与 UX 可能各自推断闸门，形成重复打断、漏确认或阶段状态不一致；尤其会损害原始意图强调的“避免决策过载”和“保持创作动量”。

**建议补回的意图：** 用一个统一的闸门规则或每个相关 FR 的可测试结果明确五个闸门、通过条件、回退行为，并声明其他阶段默认自动推进且支持随时介入。

### 差距 4：“导演工作室 / 创作者归属感 / 创作动量”被生产线语言弱化

**类型：** 体验语气与产品价值丢失（中高）

**原始意图：** 产品是一间“AI 漫剧导演工作室”，AI 以创作团队姿态主动共创；最终作品不仅要质量合格，还要让用户保有“创作者归属感”。核心价值明确要求减少等待、决策过载和全量返工造成的创作动量丢失。

**PRD / 附录现状：**

- 愿景保留“AI 工作室”，市场定位则改为“可控 AI 漫剧生产线”。
- 用户控制、自然语言反馈、持续预览和局部重做分别被 FR 化，但“用户是否仍感觉作品属于自己”“系统是否保持创作动量”没有被保留为体验原则、旅程验收或观察指标。
- 成功指标主要测创意匹配、耗时、完成率和返工范围，无法判断 AI 主动程度是否造成夺权感，也无法判断确认与等待是否让创作者失去投入感。

**影响：** 功能可能全部通过验收，产品体验却退化成自动化生产管线：结果与 idea 接近，但用户不理解 AI 做了什么、不能形成共同创作感，或被过多等待与确认打断。

**建议补回的意图：** 在体验原则或 UJ 验收中保留“AI 主动但用户拥有最终创作主权”“每个关键结果都能看出与原始 idea 和用户反馈的联系”；内部试产至少观察确认负担、等待中断和创作者归属感，而不必立即设硬性外部 KPI。

### 差距 5：“完成优先”的降级边界和缓存成本手段没有被完整承接

**类型：** 决策原则 / 机制遗漏（中）

**原始意图：** 平台“优先保证作品完成，再逐层提升质量”；预算或时间不足时可以降低镜头复杂度或运镜，但不得截断故事，也不得静默降级为不合格形态。正式生产明确依赖资产复用、缓存、并行生成和局部重做控制 Seedance 消耗；首版功能还必须明确贡献于质量、效率或成本至少一项。

**PRD / 附录现状：**

- PRD 强力保留了故事闭环、全片动态、预算暂停、资产复用、并行和局部重做。
- 但未明确“允许降低镜头复杂度或运镜”的合格降级区间，也未形成“完成优先、逐层提质”的冲突决策顺序。
- `缓存` 没有成为 FR、NFR 或 addendum.md 的生产机制，只有避免无效重生成的结果指标，无法保证可复用缓存被设计。
- “每项首版功能必须贡献于质量、效率或成本”的范围准入规则没有进入 PRD。

**影响：** 当预算、时限和质量发生冲突时，团队可能只剩“继续高规格生成”或“暂停”两种选择，遗漏原始意图允许的、仍满足质量底线的简化方案；成本架构也可能缺少缓存这一明确手段。

**建议补回的意图：** 在质量/预算策略中定义允许简化与禁止降级的边界；在附录保存缓存机制要求；把三项目标贡献作为 MVP 变更与增项的评审准则，而非强行制作 FR 追踪矩阵。

## 4. 已被良好承接的关键意图

- 非专业创作者无需影视语言或模型参数即可开始。
- AI 大胆扩写，但用户锁定设定不可被静默覆盖。
- 概念样片用于尽快验证角色、风格和戏剧卖点，且属于非正式产物。
- 自然语言反馈可转化为候选修改，并支持修改前后对比。
- 故事必须闭环，故事弧结局不得以未兑现悬念替代。
- 创作宪法、连续性账本、剧组资产及跨镜头引用均有功能承接。
- 可发布版本必须全片完整动态，不得用动态漫画或静态推拉换取速度或成本。
- 长流程恢复、持续预览、并行任务、局部重做和预算上限均有可测试要求。
- Seedance 2.0 被保留为主要视频引擎，同时节点配置、主备边界和产物配置快照保持可替换、可追溯。
- 质量、效率、成本三项成败方向被扩展成指标与反指标，且没有把 API 成功率误当成作品成功率。

## 5. 对账结论

当前 PRD 不是方向性偏离，而是 **主闭环完整、少数关键边界和体验语义变薄**。定稿前最应优先处理差距 1 至差距 3，因为它们会直接改变 MVP 范围或导致 UX、架构和测试对自动推进与确认行为产生不同解释；差距 4 和差距 5 可通过体验原则、附录机制及试产观察项补强，无需把 PRD 扩写成技术设计。
