# AI 漫剧创作平台 — Experience Spine

> 当前为 UX 工作稿。本文件定义信息架构、交互行为、状态、关键旅程与无障碍底线；视觉语言、色彩、字体和形状由 `DESIGN.md` 定义。若原型与本文件冲突，以本文件为准。

## 1. 体验北极星

让一个没有影视经验的创作者，在始终知道“作品进行到哪里、下一步是什么、还要花多少钱”的前提下，尽快获得“我的想法真的变成视频了”的满足感。

平台不是一套要求用户操作每个生产节点的工作流工具，也不是一个只靠聊天、让作品状态消失在消息记录里的生成器。它是一间由 AI 主动工作的创作工作室：用户负责提出意图、判断方向和批准关键投入，系统负责补齐专业细节、执行生产和解释结果。

## 2. 基础形态

- **主形态：** 桌面优先的响应式 Web 应用。
- **首要用户：** 无影视制作经验、希望快速完成多集 AI 短剧的新手创作者。
- **创作模式：** AI 大胆扩写，用户在少数关键节点确认；已锁定设定不得被静默改变。
- **默认复杂度：** 普通创作者不接触模型、提示词、采样参数和节点配置。
- **输出边界：** MVP 形成并受控导出内部验证版本，不提供自动公开发布。
- **持续性：** 用户关闭网页或离开项目后，长任务继续执行；返回时从持久化状态恢复。

## 3. 体验原则

### 3.1 先交付“活起来”的瞬间

在完整生产前先生成受控预算的高潮样片或概念预告。第一个体验高潮不是看到一份长剧本，而是看到自己的创意第一次成为可观看的视频。

### 3.2 让新手判断结果，不让新手配置技术

使用“像不像你想的故事”“角色感觉是否正确”“哪里需要调整”等自然语言问题。影视术语可作为解释，不作为完成任务的前置知识。

### 3.3 自动推进，但不越过昂贵决定

低风险步骤默认连续执行；涉及方向锁定、高返工或高成本投入时进入确认闸门。预算触顶、设定冲突和治理阻断随事件出现，不被埋进普通通知。

### 3.4 始终保留作品感，而非任务感

进度以“你的作品正在形成”表达，任务数和模型节点只作为辅助诊断。主界面优先展示已完成片段、剧集、角色和下一项可见成果。

### 3.5 修改应当局部、可预览、可撤销

用户指出一个角色、镜头、台词、声音或字幕后，系统先解释影响范围和成本，再生成修改候选。原版本持续可看，用户确认后才替换当前采用版本。

### 3.6 预算是护栏，不是恐吓

任何付费生成前展示金额、预算占比和生成目的。预算不足时优先提供不破坏故事完整性、锁定设定和完整动态底线的调整方案。

## 4. 信息架构

### 4.1 全局层级

| 一级区域 | 入口 | 主要用途 | MVP |
|---|---|---|---|
| 作品 | 默认首页、全局侧栏 | 创建、继续、筛选和归档作品项目 | 是 |
| 任务中心 | 全局侧栏、状态入口 | 查看跨作品运行中、等待决定、失败和已完成任务 | 是 |
| 资产库 | 全局侧栏 | 查看项目内产生的角色、场景、道具、声音等剧组资产 | 是，以项目归属为主 |
| 数据看板 | 内部运营入口 | 按作品、阶段、模型和失败类型查看质量、效率与成本 | 内部角色 |
| 系统配置 | 管理员入口 | 配置各节点模型、版本、参数模板、凭证、配额和质量档位 | 管理员 |
| 账号与设置 | 头像菜单 | 账号、主题、通知、数据与安全设置 | 是 |

普通创作者默认只看到“作品、任务中心、资产库”。数据看板和系统配置由角色权限决定，不以禁用菜单干扰普通用户。

端到端构图与转场参考：[Frochy 8 屏流程线框](wireframes/flow-frochy-end-to-end-2026-07-13.excalidraw)。该线框说明信息架构与关键转场，具体行为以本文件为准。

### 4.2 作品中心

作品中心是冷启动首页，不使用空洞的数据仪表盘。

每张作品卡展示：

- 封面或最新可播放片段；
- 作品名与一句创意锚点；
- 当前阶段和下一个可见成果；
- 状态：需要你确认、生成中、已暂停、需要处理、已完成；
- 已用预算 / 预算上限；
- 最近更新时间。

排序优先级为：需要用户决定 → 可以继续推进 → 生成中 → 已完成。首次使用时，主区域直接呈现 idea 输入框和一个“从一个想法开始”的主要动作。

### 4.3 单作品工作台

采用“阶段流水线为主、AI 对话为辅”的混合结构。

#### 顶部：作品状态栏

- 作品名与返回作品中心；
- 全局保存状态；
- 已用、已预留和剩余预算；
- 暂停 / 继续；
- 最新成片预览；
- 当前需要用户决定的事项。

#### 上方：六阶段轨道

| 阶段 | 用户看到的结果 | 内含生产能力 | 常规确认闸门 |
|---|---|---|---|
| 1. 创意 | 创意锚点、创意简报、概念样片 | Idea 共创、方向扩写、概念验证 | 创意简报 |
| 2. 故事 | 剧集规划、故事大纲、角色设定、剧本 | 多集结构、故事完整性、创作宪法 | 故事大纲与角色设定 |
| 3. 视觉 | 角色与场景资产、分镜、镜头清单、样片 | 图片生成、剧组资产、连续性规则 | 分镜与样片 |
| 4. 制作 | 持续增加的完整动态镜头、配音与音乐 | Seedance 视频生成、声音生成、并行任务 | 无常规闸门 |
| 5. 后期 | 可播放粗剪、字幕、音轨和修改版本 | 自动剪辑、字幕、局部重做 | 粗剪成片 |
| 6. 成片 | 质量报告、内部验证版本、导出记录 | QG-1 至 QG-6、转码、受控导出 | 内部验证版本 |

阶段可以回看，但未满足依赖时不能任意跳过。轨道只呈现用户理解的结果名称，不直接展示模型节点图。

#### 中部：当前产出画布

画布根据阶段切换内容形态：

- 创意阶段：创意简报与竖屏概念样片并排；
- 故事阶段：故事弧、剧集卡、角色卡和可展开剧本；
- 视觉阶段：分镜序列、角色 / 场景资产和锁定状态；
- 制作阶段：按剧集和镜头组织的生成矩阵，优先展示可播放结果；
- 后期阶段：简化时间线、播放器、字幕和音轨；
- 成片阶段：整片播放器、质量门、成本总结和导出。

用户点击任一产出物，都能看到来源、当前版本、锁定状态和“告诉 AI 怎么改”。专业元数据收在“查看制作详情”内。

#### 右侧：AI 共创面板

AI 共创面板始终与当前所选产出物绑定，不是脱离上下文的通用聊天框。

- 顶部明确当前作用范围，例如“正在修改：第 2 集 / 镜头 08 / 女主台词”；
- 显示本次会使用的锁定设定，并在使用作品记忆时提醒；
- 接受自然语言、参考图片和直觉评价；
- 先生成修改方案与影响摘要，再请求执行高成本修改；
- 含糊反馈一次只追问一个最相关问题；
- 用户可以查看、撤销和重新采用历史版本。

#### 底部：生产任务抽屉

默认折叠，只显示“12 个镜头生成中 · 预计下一预览 4 分钟 · 已预留 ¥X”。展开后显示任务、尝试次数、成本和失败原因。任务抽屉用于解释生产，不抢占作品画布。

### 4.4 作品级辅助区域

| 区域 | 用途 | 关键规则 |
|---|---|---|
| 创作设定 | 查看原始 idea、创意锚点、创作宪法和连续性账本 | 锁定项突出显示；修改锁定项必须展示下游影响 |
| 剧组资产 | 查看角色、服装、场景、道具、声音与风格规则 | 每项显示采用版本、引用镜头和一致性状态 |
| 版本记录 | 查看闸门确认、修改候选、预算变化和成片版本 | 以用户可理解的事件描述，不以模型日志为主 |
| 制作详情 | 查看任务、模型配置快照、质量结果和成本明细 | 普通用户可读，管理员可进入技术详情 |

## 5. Voice and Tone

产品说话像一位可靠、懂制作但不卖弄术语的共同创作者。它主动解释结果和后果，不假装“魔法已经完成一切”，也不把供应商错误码丢给用户。

| 场景 | 使用 | 避免 |
|---|---|---|
| 启动创作 | “先说最想表达的冲突、人物或画面，剩下的交给 AI 展开。” | “请填写完整分镜提示词。” |
| 生成中 | “12 个镜头正在创作，下一段连续预览预计 4 分钟可看。” | “任务执行中，进度 63%。” |
| 需要确认 | “这个方向值得继续拍吗？” | “是否确认当前节点输出？” |
| 局部修改 | “只会重做镜头 08，并同步替换它的配音和字幕。” | “将重新运行下游依赖。” |
| 预算阻断 | “新增任务已暂停，已完成内容不会丢失。” | “余额不足，任务失败。” |
| 成片完成 | “你的故事已经成为一部完整短剧。” | “工作流执行成功。” |

微文案使用短句、具体动词和结果导向按钮。主要动作使用“确认故事并继续”“只重做镜头 08（预计 ¥X）”等表述，不使用含糊的“确定”“OK”。

## 6. Component Patterns

行为规范与 `DESIGN.md` 的视觉 token 共同构成组件契约。

| 组件 | 使用位置 | 行为规则 | 视觉引用 |
|---|---|---|---|
| 六阶段轨道 | 单作品工作台 | 回看已完成阶段；未满足依赖时不能跳过；修改历史阶段先做影响分析 | `{colors.primary}`、`{colors.accent-cyan}` |
| 确认闸门 | 五类常规确认点 | 先浏览成果，再显示判断事项、下一步成本和三个明确动作；不使用小模态框 | `{components.gate-card}`、`{rounded.lg}` |
| AI 共创面板 | 工作台右侧 | 始终绑定当前产出物；高成本操作先给影响摘要，再进入确认 | `{components.ai-panel}` |
| 视频预览 | 样片、制作、后期、成片 | 保持 9:16；持续显示清晰的“AI 生成内容”标识；支持字幕和键盘播放 | `{components.preview-frame}` |
| 预算条 | 顶部状态栏、闸门、阻断卡 | 同时展示已消耗、已预留、剩余；付费动作展示最大计费责任 | `{colors.warning}`、`{typography.data}` |
| 修改候选卡 | 局部重做 | 原版与候选并存；候选通过检查也不会自动采用；支持撤销 | `{colors.accent-cyan}`、`{colors.border-strong}` |
| 阻断卡 | 预算、设定、治理阻断 | 展示原因、安全成果、最小影响、成本和具体选项；阻断解除前不自动继续 | `{colors.destructive}`、`{colors.surface-raised}` |
| 质量门卡 | 成片阶段 | 逐项展示证据、阻断和提醒；最终状态在创作者评分完成后计算 | `{colors.success}`、`{colors.surface-elevated}` |

## 7. State Patterns

| 状态 | 出现位置 | 处理 |
|---|---|---|
| 冷启动 | 作品中心 | 直接显示 idea 输入和预算上限；不展示空数据仪表盘 |
| 正在创作 | 作品卡、制作阶段 | 显示已完成成果、正在做什么和下一个可见成果，不只显示百分比 |
| 需要确认 | 阶段轨道、作品卡 | 将项目排在作品中心前列，进入完整确认页面 |
| 可以预览 | 作品卡、阶段轨道 | 使用 `{colors.accent-cyan}` 与文字提示，不强迫立即确认 |
| 预算 70% / 90% | 顶部状态栏、任务抽屉 | 使用 `{colors.warning}`，解释在途责任和剩余可执行范围 |
| 预算 100% | 全局、作品工作台 | 暂停新增付费任务，保留已完成成果和可查看内容 |
| 自动恢复中 | 任务抽屉 | 告知受影响最小范围、尝试次数和预算，不中断其他成功任务 |
| 无法自动恢复 | 阻断卡 | 提供可解释选项；不得静默降级为静态推拉或动态漫画 |
| 候选已生成 | 后期、局部重做 | 原版继续采用，候选进入 A/B 对比；用户明确采用后才替换 |
| 质量提醒 | 成片质量门 | 根据下表判断谁能接受；接受记录进入版本证据 |
| 质量阻断 | 成片质量门 | 不能确认内部验证版本，也不能导出 |
| 内部版本已确认 | 成片阶段 | 状态锁定并记录确认；授权账号随后获得独立“导出内部版本”动作 |

### 7.1 质量提醒与覆盖权限

| 质量门 | 提醒处理 | 阻断处理 |
|---|---|---|
| QG-1 故事完整性 | 创作者可接受节奏或悬念比例提醒 | 故事弧缺失或未兑现悬念必须修复 |
| QG-2 锁定设定与连续性 | 轻微且不影响识别的偏差可复核 | 修改创作宪法后重检，不能直接覆盖 |
| QG-3 创意匹配 | 仅创作者本人可以确认 3 分提醒 | 低于 3 分或锚点缺失必须修改 |
| QG-4 完整动态与画面 | 内部审核人与创作者共同接受轻微偏差 | 静态替代、崩坏、缺失或不可播放不能覆盖 |
| QG-5 音画字幕 | 创作者可接受不影响理解的轻微偏差 | 关键台词、字幕含义或音画同步问题必须修复 |
| QG-6 技术与受控导出 | 无可覆盖提醒 | 规格、标识、权利或权限阻断均不可覆盖 |

## 8. Interaction Primitives

- **点击：** 选择产出物、打开详情、播放和执行明确动作。
- **双击：** 不承担关键操作，避免新手发现成本。
- **拖拽：** MVP 不作为主要编排方式；后期镜头调整优先使用明确的移动动作。
- **键盘：** `Space` 播放 / 暂停，方向键细调时间点，`Esc` 关闭最上层浮层，`Cmd/Ctrl+Enter` 提交当前自然语言反馈。
- **自然语言：** 默认作用于当前选择；未选择时，AI 必须先确认作用范围。
- **选择后修改：** 播放器时间点、剧集卡、角色卡、分镜和字幕行都可以成为反馈锚点。
- **版本采用：** 生成候选与采用候选是两个动作；采用后仍提供撤销入口。
- **高成本动作：** 不允许由聊天消息直接触发扣费，必须经过影响与成本确认。
- **模态层级：** 最多一层；确认闸门和复杂阻断使用页面内区域，不堆叠对话框。

全局禁用：无限重试、自动公开发布、仅悬停可见的关键动作、只靠颜色表达状态，以及在用户不知情时改变锁定设定。

## 9. 导航与状态规则

### 9.1 状态优先于百分比

长流程不使用一个无法解释的总百分比。作品级状态采用：

- **需要你确认：** 到达常规闸门；
- **正在创作：** 系统可自动推进；
- **可以预览：** 已有新成果，无需立刻决定；
- **需要处理：** 预算、设定、质量或治理问题阻断；
- **已暂停：** 用户或系统停止新增任务；
- **已完成：** 内部验证版本已确认。

若展示阶段进度，必须同时说明“已完成什么、正在做什么、下一个成果是什么”。

### 9.2 五类常规闸门

闸门使用同一交互骨架：

1. 先展示本阶段成果，而非先弹确认框；
2. 用三句话解释“AI 做了什么、需要你判断什么、确认后会发生什么”；
3. 展示下一阶段预计新增成本和时间区间；
4. 提供“确认并继续”“告诉 AI 怎么改”“暂时停在这里”；
5. 确认记录包含采用版本、确认人和时间。

闸门不是模态弹窗。它是画布中的完整确认页面，允许用户先浏览、播放和比较。

### 9.3 事件型确认

预算触顶、锁定设定冲突和治理阻断使用高可见度的阻断卡，明确：

- 发生了什么；
- 已完成成果是否安全；
- 受影响的最小范围；
- 已消耗、已预留和剩余预算；
- 系统已经尝试过什么；
- 每个可选处理的结果、成本和质量影响。

不得用“继续”作为含糊按钮。按钮使用具体动词，例如“只重做镜头 08（预计 ¥X）”“提高预算至 ¥Y”“保留原设定并改写本段”。

## 10. 核心用户旅程

### Journey 1 — Frochy 从 idea 到第一个高潮样片

**情境：** Frochy 看到一个热门题材，只有模糊剧情念头，希望快速判断是否值得继续。

1. Frochy 进入作品中心，在大输入框写下 idea。
2. 他设置单部作品预算上限；集数、时长、题材和风格保持“交给 AI”。
3. 系统创建作品，保留原始文字，并生成创意锚点、核心冲突、目标观众和大胆扩写内容。
4. 画布并排显示“你原本说的”与“AI 补充的”；AI 新增内容不伪装成用户设定。
5. Frochy 修改一处角色动机并锁定，确认创意简报。
6. 系统展示概念样片用途、估算成本及预算占比。Frochy 选择生成。
7. 工作台进入“正在创作”，允许他离开；任务抽屉持续显示下一预览时间。
8. 样片完成后，作品卡和站内提醒显示“你的第一个片段可以看了”。
9. **体验高潮：** Frochy 播放竖屏高潮样片，第一次看到脑海中的角色在完整动态画面中表演。
10. 播放结束后只问三个直觉问题：故事像不像、角色对不对、是否值得继续；文字反馈始终可用。

**失败恢复：** 样片失败时保留创意简报。系统先在预算内自动恢复；仍失败则展示已消耗金额、原因和“换一种安全策略重试 / 暂停并保留项目”，不要求 Frochy理解模型错误码。

### Journey 2 — Frochy 确认完整故事而不是连续挖坑

**情境：** 样片方向成立，Frochy 希望 AI 把它扩成多集短剧，但不懂剧作结构。

1. 系统依据故事规模建议集数与单集时长，并说明对故事完整性和预算的影响。
2. 故事画布以“总故事弧 + 剧集卡”呈现；每集卡显示本集目标、冲突、结尾方式和承诺兑现。
3. 系统标出悬念分布：默认每 10 集最多 3 集高潮切断、连续强悬念不超过 1 集、每 3 集至少兑现一次阶段性承诺。
4. Frochy 可以说“第二集太慢”“不要让女主背叛”，AI 把反馈定位到受影响的剧集、角色和伏笔。
5. 角色设定中，原始设定、AI 扩写和已锁定内容有清晰区分。
6. 系统执行故事完整性与创意匹配预检，展示尚未兑现的关键情节。
7. **体验高潮：** Frochy 不需要阅读专业格式剧本，也能从故事弧和剧集卡确认“这个故事讲完了，而且还是我的故事”。
8. 他确认故事大纲与角色设定，形成创作宪法；系统继续生成剧本、分镜和镜头清单。

**变更分支：** 若 Frochy 修改集数或时长，先展示故事弧变化、预算变化和将失效的下游产物，再让他确认。

### Journey 3 — Frochy 看着整部作品在后台形成

**情境：** 故事与视觉方向已确认，正式生产需要较长时间。

1. 系统展示生产计划：剧集数、镜头量、预计成本区间、已预留预算和首批可预览时间。
2. Frochy 确认后，互不依赖的动态镜头、声音任务并行启动。
3. 制作画布按剧集显示镜头状态，但把已完成的可播放镜头放在最前面。
4. 页面关闭后任务继续。Frochy 返回时看到“离开期间完成了 18 个镜头；第 2 集已有可连续预览片段”。
5. 70% 和 90% 预算阈值以可解释提醒出现；100% 时自动暂停新增付费任务。
6. 单镜头失败不让整部作品变红；已成功镜头保持可用，失败镜头显示为局部缺口。
7. **体验高潮：** 可连续预览从单个镜头逐渐成长为一集、再成长为整部粗剪，用户持续获得作品正在完成的证据。

### Journey 4 — Frochy 用一句话局部重做

**情境：** 粗剪中第 2 集镜头 08 的角色表情和台词不合适，其余内容满意。

1. Frochy 在播放器暂停，选择当前镜头并说：“这里她应该强忍眼泪，不是直接哭出来；台词也更克制一点。”
2. AI 共创面板复述意图，并列出影响：镜头 08 画面、对应配音、字幕；其他镜头不受影响。
3. 系统展示新增成本、预计等待时间和会继续使用的锁定角色设定。
4. Frochy 确认后，原镜头继续留在当前粗剪中，候选版本在后台生成。
5. 完成后进入 A/B 对比：同一时间点播放、台词差异、成本与质量结果并列。
6. **体验高潮：** Frochy 采用候选版本，时间线只替换镜头 08 及其音轨和字幕，其他已确认内容不重新生成。
7. 他可以撤销采用，或基于任一版本再次修改。

### Journey 5 — Frochy 处理预算或生成失败

**情境：** 正式生成接近预算上限，同时两个镜头连续不合格。

1. 系统暂停会导致越界的新付费任务，不影响已完成成果。
2. 阻断卡说明：已完成比例、失败镜头、已消耗 / 已预留 / 剩余预算、系统已尝试的恢复策略。
3. 系统提供保持质量底线的选项，例如降低非关键镜头运镜复杂度、改变允许的生成策略、只为关键镜头追加预算。
4. 系统禁止建议截断故事、改变锁定设定或把完整动态降为动态漫画。
5. 每个选项明确“将改变什么 / 不改变什么 / 预计新增成本 / 风险”。
6. **体验高潮：** Frochy 即使无法继续，也能暂停并保留全部已完成成果；若继续，则只对批准范围重新预留预算。

### Journey 6 — Frochy 确认成片并受控导出

**情境：** 粗剪已确认，平台完成最终检查。

1. 成片页面首先提供整部作品和分集播放，不以检查表遮挡作品。
2. 质量摘要按故事完整、创意匹配、连续性、完整动态、音画字幕、技术与权利六类展示。
3. 阻断项必须修复；提醒项说明影响，并允许符合权限的用户接受。
4. Frochy 对创意匹配进行 1–5 分评价；低于 3 分必须返回修改。
5. 系统展示实际总成本、阶段成本、重试成本和可用视频秒成本。
6. Frochy 完成最小素材权利声明并提交最终创意匹配评分；系统据此完成 QG-3 和总质量门判定。
7. 所有阻断项通过后，Frochy 确认内部验证版本，系统保存确认人、时间、质量结果和实际成本。
8. **最终高潮：** 作品状态变为“已完成”；授权账号随后可以使用独立的“导出内部版本”动作，按内部统一规格受控导出。页面明确说明“当前是内部验证版本，尚未公开发布”。
9. 系统保存版本、质量结果、确认记录、模型配置快照和导出记录，为未来发布能力准备。

## 11. 关键跨流程规则

### 11.1 创作记忆与设定提醒

- 当前 MVP 以项目内创作宪法和连续性账本为准；
- 右侧共创面板在使用锁定设定时显示“本次将遵循 6 条已锁定设定”；
- 若用户指令与锁定设定冲突，先指出冲突并询问是修改本次内容还是正式修改设定；
- 正式修改设定前展示受影响的剧集、资产和镜头；
- 跨作品偏好记忆属于增强项，但界面预留“记忆中心”入口，不伪装成已实现能力。

### 11.2 预算呈现

- 顶部始终展示已消耗、已预留、剩余三段，而不是只显示一个模糊余额；
- 每个付费动作都说明目的和最大计费责任；
- 预算预留在任务完成、取消或失败结算后释放差额；
- 普通创作者看到阶段和产出物成本，技术模型账单放在制作详情；
- 成本提醒不使用制造焦虑的倒计时或红色闪烁。

### 11.3 版本与采用

- “生成新版本”不等于“替换当前版本”；
- 当前采用版本始终可识别；
- 候选版本通过质量检查后仍需用户采用；
- 上游设定发生变化时，系统标记下游版本可能过期，并说明原因；
- 已锁定且依赖未变化的结果默认复用。

## 12. 响应式边界

| 视口 | 行为 |
|---|---|
| ≥ 1280px | 完整工作台：全局侧栏、中央画布、右侧 AI 共创面板同时可见 |
| 1024–1279px | 侧栏收窄为图标；右侧共创面板可折叠 |
| 768–1023px | 阶段轨道横向滚动；AI 共创面板以侧滑层打开；支持审阅和轻量修改 |
| < 768px | 支持查看进度、播放预览、处理简单确认和接收提醒；不承诺完整故事编排与后期编辑体验 |

MVP 是桌面优先 Web 产品。手机可作为“查看与确认”补充入口，不以移动端完整创作为验收目标。

## 13. 无障碍底线

- 满足 WCAG 2.1 AA 核心要求；
- 所有确认、预算和错误状态不能只依赖颜色；
- 键盘可完成全局导航、打开产出物、播放控制、确认闸门和关闭浮层；
- 焦点顺序遵循左侧导航 → 阶段轨道 → 主画布 → AI 共创 → 任务抽屉；
- 视频提供字幕；关键台词与字幕具有关联文本；
- 动态进度更新通过适度的 `aria-live` 通知，避免每个任务变化都打断屏幕阅读器；
- 减少动态偏好开启后，禁用非必要光效、自动转场和庆祝动画；
- 触控目标不小于 44×44 CSS px；
- 阻断信息使用明确标题、原因、影响和动作，不只显示错误码。
