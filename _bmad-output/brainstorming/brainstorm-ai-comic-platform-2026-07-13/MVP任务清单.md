# AI 漫剧创作平台首版 MVP 任务清单

## 1. MVP 目标与验收原则

首版面向缺乏影视经验、追求快速产出的非专业创作者，提供一间 AI 漫剧工作室：快速把一句 idea 兑现为故事完整、全片动态、保持用户设定与角色一致、并让用户保有创作者归属感的作品。

首版只交付已经确认的六项 Must，形成从 idea 到完整漫剧的最小产品闭环。所有 Must 必须至少对以下一个最高验收维度有明确贡献：

- **视频质量**：故事完整、全片动态、用户设定不被擅自改动、角色和世界规则前后一致。
- **生成效率**：缩短首次可观看成果用时，减少等待、决策过载与全量返工，支持并行生成、局部重做和无损续作。
- **成本控制**：方向确认前使用受控预算与快速模式，通过资产复用、缓存、局部重做和模型配置降低无效生成成本。

## 2. 实施阶段顺序与依赖总览

| 阶段 | Must | 实施目标 | 前置依赖 | 阶段验收结果 |
|---|---|---|---|---|
| 0 | M6 可恢复编排与管理员模型配置 | 先建立各节点可执行、可恢复、可配置、可追踪的流水线底座 | 无 | 后续每个生成节点均能接入配置、保存进度并记录模型配置快照 |
| 1 | M1 共同创作入口与概念样片 | 把模糊 idea 快速变成可观看、可反馈的方向验证成果 | M6 基础节点编排与模型配置 | 用户无需影视术语即可提交 idea、看到概念样片并确认或修正方向 |
| 2 | M2 故事、脚本与分镜 | 将确认方向转为故事完整、可生产的剧本、分镜与镜头清单 | M1；M6 | 形成可理解的故事闭环及可供后续生产的镜头计划 |
| 3 | M3 设定与基础资产一致性 | 固化用户设定，建立可复用剧组资产与一致性约束 | M1；M2；M6 | 角色、世界规则和基础资产可复用，并能在生成前后约束冲突 |
| 4 | M4 Seedance 全动态镜头生产 | 基于分镜和剧组资产批量生成完整动态镜头 | M2；M3；M6 | 所有可发布镜头均为完整动态视频，失败或修改只重做必要范围 |
| 5 | M5 声音、剪辑、字幕与成片 | 汇总动态镜头，完成配音配乐、剪辑、字幕与发布版本确认 | M2；M4；M6 | 产出故事完整、视听可理解、可由用户确认的发布版本 |

> M6 是横跨全流程的底座，不代表普通创作者需要选择模型。管理员负责节点级配置，创作者前台保持共同创作与少量关键选择。

## 3. 六项 Must 任务清单

### M6. 可恢复编排与管理员模型配置

**目标**：让从 idea 到成片的各节点可以自动衔接、保存阶段产物、失败后恢复，并允许管理员配置节点对应的模型与参数。

#### M6.1 工作流节点与阶段产物

- [ ] 定义首版节点：创意输入、概念样片、故事大纲与角色设定、脚本、分镜与镜头清单、基础资产、动态镜头、配音配乐、剪辑、字幕、发布版本。
- [ ] 定义各节点的输入、输出和完成状态，使下游只能消费已完成的阶段产物。
- [ ] 保存节点进度与阶段产物，支持中断后从已完成节点继续，而非整条流水线重来。
- [ ] 支持局部重做：修改某一阶段后，只重新执行必要的后续节点。
- [ ] 支持可持续预览的阶段成果，让用户始终接近一个可发布版本。

**依赖**：无，是其他 Must 的共同底座。

**验收结果**：一次创作可以在任意已完成节点后退出并继续；单节点失败或局部修改不会强制从 idea 重新生成全部内容。

**贡献**：提升**生成效率**，避免中断与全量返工；通过局部重做降低**成本**。

#### M6.2 管理员节点配置

- [ ] 提供系统配置界面，按工作流节点配置模型提供方、模型版本、参数模板、凭证和配额。
- [ ] 每个节点至少可配置主模型、备用模型及不同质量档位。
- [ ] 将节点配置版本化，并为每次阶段产物记录实际使用的模型配置快照。
- [ ] 当备用模型无法满足角色一致性或完整动态要求时，暂停并解释原因，不静默降级为不合格成片。
- [ ] 普通创作者默认不选择模型，前台只呈现创作任务所需的直观选择和反馈。

**依赖**：M6.1 的节点定义。

**验收结果**：管理员可以修改指定节点的模型和参数；已有产物可查到其配置快照；主模型不可用且备用模型不达质量底线时，系统明确暂停。

**贡献**：质量底线与配置快照保障**视频质量**和可复现性；主备配置与质量档位兼顾**生成效率**和**成本控制**。

### M1. 共同创作入口与概念样片

**目标**：让新手只用自然语言表达 idea，AI 主动扩写，并尽快交付高潮样片或概念预告作为“首次惊喜时刻”。

#### M1.1 idea 接收与创意锚点

- [ ] 提供自然语言 idea 输入入口，不要求用户掌握影视术语或完整回答抽象产品问题。
- [ ] 从原始 idea 提炼不可轻易偏离的创意锚点，明确用户已设定的角色、关系、世界规则与关键意图。
- [ ] AI 默认大胆补齐人物、冲突、世界观、反转和剧集钩子，但不得擅自修改用户设定。
- [ ] 在需要用户判断时，只要求“喜欢与否”或一句自然反馈，由系统把直觉反馈翻译为专业修改。

**依赖**：M6.1；调用生成能力时依赖 M6.2 的节点配置。

**验收结果**：输入一句模糊 idea 后，系统能形成带有明确创意锚点的扩写方向；扩写结果不改动已识别的用户设定。

**贡献**：减少表达门槛与决策过载，提升**生成效率**；创意锚点提高创意匹配度与**视频质量**。

#### M1.2 概念样片与方向确认

- [ ] 优先生成高潮样片或概念预告，验证核心角色、视觉风格和戏剧卖点。
- [ ] 概念样片使用受控预算与快速模式，并明确标记为非正式内容。
- [ ] 允许用户围绕作品直接给出自然反馈，系统追问至多一个上下文相关问题并给出修改候选。
- [ ] 展示修改前后结果，支持确认、改写或丢弃样片方向。
- [ ] 方向确认后，允许正式脚本阶段继承样片中被认可的内容。

**依赖**：M1.1；M6.1；M6.2。

**验收结果**：用户可在正式全量生产前看到可播放的概念样片，完成一次“保留、修改或丢弃”的方向决策；未确认方向不进入高成本批量镜头生产。

**贡献**：缩短首次可观看成果用时，提升**生成效率**；提前验证方向减少高成本返工，改善**成本控制**；核心角色与视觉方向提前对齐，提升**视频质量**。

### M2. 故事、脚本与分镜

**目标**：把已确认的创作方向转化为故事完整、可执行的脚本、分镜和镜头清单。

#### M2.1 故事大纲与角色设定确认

- [ ] 基于创意锚点生成故事大纲、主要角色设定及世界规则。
- [ ] 确保完整短篇或阶段性故事弧具备开端、冲突、推进和可理解的阶段性结局。
- [ ] 设置“故事大纲与角色圣经”关键确认闸门，只在可能改变作品方向或导致高额返工时要求用户确认。
- [ ] 用户反馈由系统转译为故事或角色修改，并保留用户未要求改变的设定。

**依赖**：M1.1；M1.2；M6。

**验收结果**：用户确认后的故事大纲能够说明本故事弧的主要冲突如何推进及兑现；角色设定与创意锚点无冲突。

**贡献**：叙事闭环和设定对齐提升**视频质量**；在分镜与视频生成前确认高返工风险内容，提升**生成效率**并控制**成本**。

#### M2.2 脚本、分镜与镜头清单

- [ ] 依据已确认大纲自动细化脚本。
- [ ] 将脚本转为分镜和镜头清单，为每个镜头关联角色、场景、道具、动作参考和台词或声音需求。
- [ ] 确保镜头序列能够完整传达当前故事弧，不因预算或时间不足而截断故事。
- [ ] 设置“分镜与样片”关键确认闸门，让用户以直观候选结果确认叙事与视觉方向。
- [ ] 当用户修改局部剧情或镜头时，只标记必要范围进入后续重做。

**依赖**：M2.1；M6。

**验收结果**：每段脚本均有可生产的镜头承载；镜头按顺序播放时，开端、冲突、推进和阶段性结局信息完整；局部修改不会默认推翻全部分镜。

**贡献**：可生产分镜与故事信息完整性提升**视频质量**；局部修改范围降低返工量，改善**生成效率**和**成本控制**。

### M3. 设定与基础资产一致性

**目标**：在批量生成前建立可复用剧组资产，并用创作宪法与连续性账本约束用户设定和角色一致性。

#### M3.1 创作宪法与连续性账本

- [ ] 将创意锚点、用户设定、角色外形、性格、关系、能力和世界规则写入可锁定的创作宪法与连续性账本。
- [ ] 每个后续生成节点执行前注入相关约束。
- [ ] 每个生成节点完成后检查产物与锁定设定、角色状态和世界规则是否冲突。
- [ ] 发现冲突时阻止不一致产物直接进入下一阶段，并将问题定位到需要重做的局部内容。

**依赖**：M1.1；M2.1；M6。

**验收结果**：已锁定的用户设定不会被后续生成擅自改动；角色在脚本、分镜、资产和镜头之间保持可核对的一致性；冲突可被识别并限制在局部重做范围。

**贡献**：连续性约束直接提升**视频质量**；提前发现冲突与局部修正提升**生成效率**并减少浪费成本。

#### M3.2 可复用剧组基础资产

- [ ] 在批量镜头生产前建立角色多视图与表情、服装版本、场景、道具、声音、动作参考和风格规则。
- [ ] 为资产保存版本，并记录镜头对资产版本的引用关系。
- [ ] 允许后续镜头复用已确认资产，避免相同角色、场景和风格反复从零生成。
- [ ] 首版资产修改只要求保留版本与引用关系；更完整的资产影响分析留在 Should 范围。

**依赖**：M2.2；M3.1；M6。

**验收结果**：批量镜头生成前具备可引用的基础资产；同一角色跨镜头使用同一已确认版本；旧资产版本和已有镜头引用关系不丢失。

**贡献**：资产复用与版本一致性提升**视频质量**，减少重复生成并改善**生成效率**和**成本控制**。

### M4. Seedance 全动态镜头生产

**目标**：以 Seedance 2.0 为主要视频生成模型，基于已确认的分镜与剧组资产批量生成完整动态视频镜头。

#### M4.1 完整动态镜头生成

- [ ] 将镜头清单、关联资产、创作宪法和连续性约束组装为视频生成任务。
- [ ] 以 Seedance 2.0 作为主要视频生成模型执行镜头生成。
- [ ] 可发布成片中的所有镜头均生成完整动态视频，不以动态漫画、静态叙事或“关键镜头高动态、普通镜头轻动态”作为常规降级方案。
- [ ] 支持后台并行生成互不依赖的镜头，并持续展示已完成镜头的预览。
- [ ] 使用已确认资产和缓存结果，避免未变化内容重复生成。

**依赖**：M2.2；M3.1；M3.2；M6.2。

**验收结果**：镜头清单中的每个可发布镜头都有完整动态视频结果；并行任务不破坏镜头与资产版本的对应关系；未变更镜头不会因局部修改被无条件重做。

**贡献**：完整动态基线与一致性约束保障**视频质量**；并行生成、资产复用和缓存提升**生成效率**并控制**成本**。

#### M4.2 镜头质检与局部重做

- [ ] 检查生成镜头是否满足角色一致性、用户设定和完整动态要求。
- [ ] 对不合格镜头给出明确原因，不允许静默使用低于质量底线的备用模型结果。
- [ ] 支持只重做失败或被用户否决的镜头，并继续复用未受影响的资产和镜头。
- [ ] 将通过质检的镜头锁定为后续剪辑输入。

**依赖**：M4.1；M3.1；M6.1。

**验收结果**：不一致或非完整动态的镜头不能进入成片；用户否决单个镜头时，只需重新生成该镜头及确有依赖的内容。

**贡献**：质量底线检查提升**视频质量**；镜头级重做提升**生成效率**并避免全片重生成成本。

### M5. 声音、剪辑、字幕与成片

**目标**：把通过质检的完整动态镜头自动组装为有配音配乐、剪辑和字幕的故事完整成片，并由用户确认发布版本。

#### M5.1 声音与字幕

- [ ] 根据脚本和镜头需求生成或配置配音、配乐及字幕。
- [ ] 让台词、声音和字幕与镜头顺序及故事信息保持对应。
- [ ] 将声音与字幕产物纳入可恢复节点，单项失败或修改时不重做无关视频镜头。

**依赖**：M2.2；M4.2；M6。

**验收结果**：主要剧情信息可以通过画面、声音和字幕被理解；修改一处配音或字幕不触发无关镜头重新生成。

**贡献**：视听信息完整提升**视频质量**；独立节点与局部修改提升**生成效率**并控制重做**成本**。

#### M5.2 自动剪辑、粗剪确认与发布版本

- [ ] 按脚本与分镜顺序自动完成镜头剪辑，并合入配音、配乐和字幕。
- [ ] 设置“粗剪成片”关键确认闸门，用户可直接反馈故事、镜头、表演或声音问题。
- [ ] 优先检查故事完整性：完整短篇或阶段性故事弧必须完成叙事闭环。
- [ ] 短剧单集允许在高潮处切到下一集，但不得把连续悬念当作故事兑现；首版不实现用户可配的悬念比例规则，该能力保留在 Should。
- [ ] 完成必要局部修正后设置“发布版本”确认闸门，由用户明确批准最终版本。
- [ ] 默认不自动公开发布；首版交付的是经用户确认的发布版本。

**依赖**：M5.1；M4.2；M6.1。

**验收结果**：成片全程由完整动态镜头构成；故事弧的承诺得到兑现且主要信息可理解；用户完成粗剪审阅与发布版本批准；系统不会未经确认自动公开发布。

**贡献**：故事闭环、全动态与视听整合保障**视频质量**；自动剪辑和局部修正提升**生成效率**；避免无效全量返工改善**成本控制**。

## 4. 端到端 MVP 验收场景

- [ ] 非专业创作者输入一句模糊 idea，AI 主动扩写并生成不偏离用户设定的创意锚点。
- [ ] 系统使用快速模式与受控预算生成概念样片，用户通过喜欢与否或自然语言完成方向确认。
- [ ] 系统生成故事大纲、角色设定、脚本、分镜和镜头清单；故事弧具备可理解的推进与兑现。
- [ ] 系统建立连续性账本与可复用剧组资产，后续节点能引用锁定设定和资产版本。
- [ ] Seedance 2.0 批量生成全部完整动态镜头，互不依赖的镜头可并行，失败镜头可局部重做。
- [ ] 系统完成配音配乐、剪辑和字幕，用户审阅粗剪后确认发布版本。
- [ ] 任一节点中断后可从最近完成节点继续；局部修改不会默认触发全流程重做。
- [ ] 每个阶段产物可追溯到节点模型配置快照；低于角色一致性或完整动态底线的备用模型结果不会被静默采用。

当以上场景全部通过，且最终作品满足“故事完整、全片动态、设定与角色一致”，六项 Must 才构成闭环验收通过。

## 5. 首版范围边界

### Should：首版之后优先评估，不纳入本清单的交付承诺

- 偏好记忆与透明度：跨项目学习创作者的叙事、分镜、剧本、节奏、视觉和声音审美；提供记忆中心及使用提醒。
- 悬念节奏配置：允许用户设置悬念比例；已确认的默认方向为 10 集最多 3 集高潮切断，并控制连续悬念与剧情兑现节奏。
- 模型策略组高级路由：依据任务阶段、质量、预算、时限、可用性和内容能力动态路由。
- 资产影响分析：资产修改时提示受影响的剧本、分镜和已生成镜头，并支持选择性重生成。
- 多平台发布反馈：接收发布后反馈并用于后续创作。

### Could：有余力再考虑，不影响首版闭环验收

- 多人协作。
- 资产市场。
- IP 衍生。
- A/B 与智能成本优化。

### Won't：首版明确不做

- 专业非线性剪辑器。
- 通用工作流搭建器。
- 默认全自动公开发布。
- 以动态漫画替代完整动态成片。

## 6. 首版完成定义

首版不是“某个模型能够生成视频”，而是六项 Must 可以连续运行并交付一部经用户确认的完整漫剧。完成判定必须同时满足：

1. **闭环完整**：从 idea、概念样片、故事脚本分镜、设定与基础资产、Seedance 全动态镜头，到声音剪辑字幕成片全部可运行。
2. **质量达标**：故事弧完整，全片镜头为完整动态视频，用户设定不被擅自改动，角色保持前后一致。
3. **效率可感知**：用户能快速看到概念样片，阶段成果持续可预览，节点可恢复，镜头可并行并支持局部重做。
4. **成本受控**：方向未确认前采用受控预算与快速模式，正式生产复用资产与缓存，局部修改不触发无关内容重生成。
5. **边界清晰**：Should、Could 与 Won't 中的能力不作为首版闭环完成的前置条件，也不得取代六项 Must。
