# Story 1.3：建立可独立构建的最小平台骨架

Status: review

## Story

作为平台研发人员，
我希望建立 Web、BFF、核心服务、体验投影和 Worker 的独立构建边界及最小契约，
从而使团队可以在统一事实所有权与兼容演进规则下并行开发。

## Acceptance Criteria

1. **独立构建边界与首版契约成立**
   - **Given** G0-1 与 G0-2 已有可复核证据，且 2026-07-14 用户明确决定直接启动 Story 1.3
   - **When** 初始化 monorepo 结构、首版 Proto、事件 Envelope、服务模块与镜像构建入口
   - **Then** Web BFF、Studio、Workflow、Budget、Asset、Model Gateway、Quality、Delivery、experience-projection、provider/media worker 均具备独立构建边界
   - **And** Go 服务不得依赖根 `go.work` 才能构建，不存在跨服务 SQL、共享业务表、跨服务 `internal`/repository/model/DAO import 或手改生成代码。

2. **契约演进门禁失败关闭**
   - **Given** Proto 或事件契约发生变更
   - **When** 执行契约 CI/本地 gate
   - **Then** breaking、unknown enum/field 和 golden vector 测试必须运行
   - **And** 破坏性变更必须以新版本并行发布，v1 只能兼容新增；业务 enum 的 0 值必须为 `*_UNSPECIFIED` 且消费者 fail-closed。

3. **local 集成环境可观测并完成最小事件往返**
   - **Given** local Docker Compose 环境启动
   - **When** 执行健康检查、Outbox/Inbox 或等价事件路径的最小事实事件往返
   - **Then** BFF、领域服务、Temporal、Kafka、MySQL、对象存储和 experience-projection 均可观测
   - **And** 日志与 trace 不包含密钥、token、媒体 URL 或敏感提示词原文；Budget、对象持久化、Quality Gate 或编排不可用时保持 fail-closed。

4. **Web 工作台骨架符合 UX token、响应式与 WCAG 基线**
   - **Given** Web 工作台骨架启动
   - **When** 在桌面、平板和手机视口验收全局导航、顶部状态栏、六阶段轨道、当前画布、AI 共创面板与任务抽屉骨架
   - **Then** 使用 `DESIGN.md` 的深色 token、4px 间距系统、明确焦点样式和六阶段布局
   - **And** 自动检查对比度、键盘导航、非颜色单一编码、44x44 触控目标和 `prefers-reduced-motion` 基线。

5. **证据可审计且范围不越界**
   - **Given** 三个原子任务均完成
   - **When** 汇总 Story 1.3 证据
   - **Then** `reports/contracts/`、`reports/observability/`、`reports/a11y/`、`reports/ui-state/` 至少保存输入、命令、输出摘要、失败恢复方式与 owner
   - **And** 本 Story 不实现 Story 1.4 的项目创建业务、不实现 Story 1.6 的真实付费闭环、不接入真实供应商、不处理真实敏感素材。

### UX / Accessibility

- 视觉系统使用 `DESIGN.md`：`#080A12` 主背景、`#0B0E18` 侧栏、`#101522` raised、`#6547D9` 主动作、`#2DD4E5` 生成/焦点、`#F4F7FF` 主文字。
- MVP 只完整验收深色主题；浅色主题不在本 Story 范围。
- 首屏必须是可用工作台骨架，不是营销页或静态说明页。
- 状态必须同时用图标/标题/文本表达，不能只靠颜色。
- 字体不得依赖联网下载；使用 `Geist, PingFang SC, Noto Sans SC, Microsoft YaHei, sans-serif` 与数据等宽栈。
- 视口边界、键盘操作、触控目标、焦点顺序、`aria-live` 克制通知和 reduced-motion 均按 `EXPERIENCE.md` 执行。
