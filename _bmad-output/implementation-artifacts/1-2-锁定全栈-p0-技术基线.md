# Story 1.2：锁定全栈 P0 技术基线

Status: review

## Story

作为平台研发与架构负责人，
我希望为运行平台所需的基础设施和工具建立可恢复、可回滚、可验证的精确基线，
从而使平台骨架、CI 和 internal-prod 不依赖猜测版本或仅在单机成立的组合。

## Acceptance Criteria

1. **全栈组件基线精确、可审计**
   - **Given** Story 1.1 的 `BASE-001`/G0-1 已有可复核的远程工具链放行证据
   - **When** 锁定 Temporal Server/Go SDK/persistence/visibility schema、MySQL 8.4 LTS、Kafka/agsarama、Nacos/Redis、S3 兼容对象存储、FFmpeg、Node/Web lockfile 与 Kubernetes 发行版
   - **Then** 签署的 `BASE-002` manifest 对每一项记录精确版本或不可变镜像 digest、许可证、依赖/兼容矩阵、配置来源、owner、审批人、证据路径与失败回滚目标
   - **And** 任一空值、`latest`、浮动 tag/分支、未解析的镜像 tag、本地缓存或未审批组合都必须使 Gate 非零失败并保持 P0 阻塞。

2. **锁定组合可在干净 integration 环境重建并验证兼容性**
   - **Given** 候选组合从 `BASE-002` manifest 开始，不复用开发机的全局 PATH、容器缓存、本地 checkout 或旧数据卷
   - **When** 运行唯一权威 `BASE-002` Gate，完成冷启动、服务/协议契约、生产消费/rebalance/DLQ、配置与缓存兼容、对象版本/加密/校验、故障注入、N/N-1 或已签署兼容窗口、升级、回滚和恢复验收
   - **Then** 证据包保存可重复命令、输入金样、版本/digest 解析结果、日志/trace、时序与完整的正负向结果
   - **And** integration 与 internal-prod 不得共享 MySQL 数据库、Kafka Topic、Temporal Namespace、Bucket 或 Secret；未能证明隔离时不得放行。

3. **故障时维持业务安全并用演练证明恢复目标**
   - **Given** Budget、对象持久化、Quality Gate、Temporal/Kafka 编排通路分别可被独立注入故障
   - **When** 执行中断点、重启、网络分区、依赖降级、备份恢复、滚动升级与回滚演练
   - **Then** 新的付费推进必须 fail-closed，已持久事实与安全成果不得丢失，Kafka 不得被当作业务事实备份
   - **And** 计时演练必须证明业务元数据 `RPO ≤ 5 分钟` 且 `RTO ≤ 2 小时`，覆盖 MySQL PITR、Temporal persistence/visibility、Kafka 恢复关系和对象引用一致性；仅有备份配置不算通过。

4. **Web 工具链可重复安装，但不越界实现 Web shell**
   - **Given** Node 镜像、包管理器版本、React 19.2/Vite 8.1.4/TypeScript 5.x 目标与最小兼容 fixture 已声明
   - **When** 在无全局包、无二次解析、无网页应用源码的干净容器中执行 frozen/immutable lockfile install 和最小 build 金样
   - **Then** 两次安装的 lockfile digest、依赖树与产物 digest 一致，不得在验证时改写 lockfile
   - **And** 本 Story 不创建 `web/` 应用、设计 token、页面、响应式布局或 WCAG 实现；这些属于 Story 1.3。

5. **FFmpeg 媒体金样满足内部 DeliveryProfile**
   - **Given** FFmpeg 8.1.2 目标镜像已解析为不可变 digest，并冻结 H.264、AAC、libass、字体与标识能力清单
   - **When** 从受控合成输入生成媒体金样并用 ffprobe/可视校验器验收
   - **Then** 输出为 9:16、1080×1920、30fps、MP4/H.264、AAC 48kHz，包含字幕烧录和独立字幕、可见 AI 标识与可验证元数据
   - **And** 字体使用仓库可获得或镜像内已锁定的中文字体，不依赖验收时临时联网下载；静态帧、无标识、错编码、无字幕或不可播放必须失败。

6. **聚合 Gate 与状态更新不得误报放行**
   - **Given** `BASE-001`、`BASE-002` 及 `NFR-DR-001` 最小 smoke 的证据和审批状态可机器读取
   - **When** 执行 Story 1.3 的前置放行检查
   - **Then** 只有 G0-1 已验证、G0-2 的全部子项 P0 100% 通过且证据可复核时，才可将 `技术基线锁定.md` 整体状态改为 `locked` 并更新 G0-2
   - **And** Story 1.1 仍为 `in-progress`、任一证据仅为本地 fixture GREEN、任一组件未锁定或任一故障/回滚/恢复场景失败时，必须保持阻塞，不得执行 Story 1.3 完整脚手架或 internal-prod 放行。
