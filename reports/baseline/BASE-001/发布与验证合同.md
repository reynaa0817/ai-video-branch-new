# BASE-001 发布与验证合同

## 不可变引用

- 发布 manifest 只记录最终 tool source 与 root dependency 双锁；本机 checkout SHA 只作调查证据，不是发布字段。
- tool source 候选必须来自规范远端可达提交/tag 或受审 PR merge SHA，并在冻结前通过 clean-build/provenance preflight。
- `root_dep_version` 使用受保护的 SemVer annotated/signed tag，建议命名 `v0.1.0-baseline.1`；发布后禁止删除、重建或 force-move。
- `tool_source_ref` 使用受保护的 annotated/signed tag，建议命名 `refs/tags/ag-core-tools-v0.1.0-baseline.1`；发布后禁止删除、重建或 force-move。
- GitHub tag ruleset `18908015`（`BASE-001 immutable ag-core refs`）已 active，覆盖 `refs/tags/v0.0.1-alpha.3` 与 `refs/tags/ag-core-tools-v*`，禁止 deletion、non-fast-forward 和 update，且当前管理员也不可 bypass。
- 候选失败时弃用原 ref 并创建递增的新候选；回滚只能恢复上一条已验证 ref。
- owner 为 Platform release owner；弃用记录必须包含原因、替代 ref、批准人和时间。

## 发布 Entry Criteria

同时满足以下条件才允许执行 push、tag 发布或 GitHub ruleset 变更：

1. GitHub repo owner 对 root dependency 与 tool source 双锁方案作出明确人工批准。
2. 执行者具备 tag 发布权限和 ruleset/tag protection 管理权限，凭据已现场验证。
3. Architecture 批准 `tool_source_sha` 与 `root_dep_sha` 的相同或差异关系。
4. 只读 hermetic preflight 已通过，且拟发布提交在规范 remote 可读取。

缺少任一条件时仅允许本地 RED/preflight；门禁以 `B001-E09` 失败关闭。

## 构建合同

- Go：`go1.25.1`，`GOTOOLCHAIN=local`；CI image 固定为 `golang:1.25.1@sha256:d7098379b7da665ab25b99795465ec320b1ca9d4addb9f77409c4827dc904211`。
- 网络：仅允许规范 GitHub remote、`GOPROXY=https://proxy.golang.org,direct` 与 `GOSUMDB=sum.golang.org` 所需流量。
- 隔离：`GOWORK=off`，每次运行创建独立 `GOMODCACHE`、`GOCACHE`、checkout 与输出目录。
- CI job：`ag-core-baseline`；PR 快速门禁目标小于 15 分钟。
- 证据路径：`reports/baseline/BASE-001/`；仓库内证据长期保留，外部大日志保留不少于 180 天并记录稳定 artifact ID。
- 七个工具固定为：`aggo`、`gendb`、`protoc-gen-go-agapi`、`protoc-gen-go-aghertz`、`protoc-gen-go-agkitex`、`protoc-gen-go-agserver`、`protoc-gen-go-agservice`。其中 `gendb` 源目录是 `tool/cmd/gen-go-db`。

## Metadata 与失败合同

- 只允许 `github.com/aif-go/ag-core` 命名空间；命中旧 GitLab 路径返回 `B001-E03`。
- 工具源码 `vcs.revision` 必须等于 `tool_source_sha`，且 `vcs.modified=false`；缺失或不一致返回 `B001-E07`。
- 五个 protoc 插件的 root ag-core 依赖版本必须等于 `root_dep_version`，该版本的远端解析 SHA 必须等于 `root_dep_sha`；不一致返回 `B001-E06`。
- 本地 `replace`、根 `go.work` 或开发机 PATH 掩盖返回 `B001-E04`。
- 错误码矩阵固定为：ref 获取 `E01`、SHA `E02`、旧路径 `E03`、本地掩盖 `E04`、工具/命名 `E05`、双锁 provenance `E06`、VCS `E07`、环境 `E08`、审批/保护 `E09`。
