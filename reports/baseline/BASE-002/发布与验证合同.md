# BASE-002 发布与验证合同

## 单一入口

本地、CI 与 ATDD 统一调用 `scripts/verify-full-stack-baseline.sh`。workflow 只负责环境编排和证据上传，不复制判定逻辑。

## 快速合同与真实 profile

- 快速合同使用独立 fixture 验证 schema、稳定错误码和证据形状，目标小于 15 分钟。
- 真实 profile 必须从空容器缓存和独立数据面执行兼容、Web 双跑、媒体金样、故障、升级、回滚与恢复。
- fixture GREEN 不等于真实集成放行；只有签署 manifest 引用的现场证据可更新 G0-2。

## 错误码

| 错误码 | 含义 |
| --- | --- |
| `B002-E01` | manifest/证据字段缺失、占位、许可证或审批缺失 |
| `B002-E02` | `latest`、浮动 ref 或镜像 digest 无效 |
| `B002-E03` | 组件、SDK、schema、lockfile 或双跑结果不兼容 |
| `B002-E04` | integration 与 internal-prod 共享资源 |
| `B002-E05` | 核心依赖失败时仍产生新付费推进 |
| `B002-E06` | 媒体规格、字幕、字体、标识或元数据失败 |
| `B002-E07` | RPO/RTO 超阈值或恢复引用不一致 |
| `B002-E08` | G0-1/G0-2 未通过却放行 Story 1.3 |

## 回滚

失败候选保留 SHA/digest 与证据，不移动既有标识。回滚到上一条已签署且仍可恢复的 BASE-002 manifest。
